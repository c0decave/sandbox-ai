# sandbox-ai 0.1.89

Two independent stability reviews of the desktop app, and what they found:

- **A crash leaves a trace:** QtWebEngine (the terminal tabs) runs inside the app; a failed check of Chromium ends it
  with SIGTRAP, which left nothing behind. Now the stacks of every thread are written to `app.log`, and the next
  start quotes them in the log window. The start script keeps the logs of the five starts before.
- **One app per user:** a second start (the login's autostart and a start by hand) shows the first one's window and
  ends - two apps overwrote each other's unapplied board changes.
- **Nothing is lost:** a hand-edited or damaged `state.json` no longer stops the app at start; saving or deleting a
  preset of your own keeps every other one (also those this version cannot read); a file that cannot be read is
  never overwritten with one value (settings, profiles, presets); the state writer survives any error and quitting
  waits for it at most 15 s; logout and SIGTERM write the state first; what is being typed in the board's inspector
  is taken before quitting and when another part is selected; changes made while Apply writes stay unapplied;
  `app.log` is rotated while the app runs.
- **Board:** a connection being dragged survives the board being made again (Delete, a theme, a project switch).
