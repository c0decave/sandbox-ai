# sandbox-ai 0.1.91

**Stability: a 25-minute soak of the app under load** (page switches, the board, questions answered, thousands of
log entries, themes, sessions coming and going, terminal tabs opened, typed into and closed), found and fixed:

- the same crash as 0.1.90's from the other side - a terminal tab while an application-wide event filter was on
  ended the app (the soak's run before the fix died after 18.5 minutes; after it, 25 minutes and more without one);
- closed terminal tabs whose command still ran kept their bridge to the terminal alive (94 after 25 minutes);
- the log window stood still up to a second at Debug with 5000 entries (at every theme and every key in its filter);
- the board's Undo grew without bound and slowed every save; it keeps 500 steps per project now;
- the state file could grow past what is read at start (every draft would have been lost): it is written compactly
  and the boards keep to a budget - Undo history goes first, every draft stays.

Also: a notification's button whose answer asks first no longer raises "Internal C++ object (Toast) already deleted"
when the notification's time runs out meanwhile.

**Performance, three more rounds:** the system theme's colours made once per palette (asked for at every paint of a
board part), the board's parts list and the log window drawn more cheaply, panels of other pages fold only when shown,
and `sandbox-ai approvals` loads the launcher for the policy only when there is a policy file.
