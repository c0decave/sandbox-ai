# sandbox-ai 0.1.198

**What came since 0.1.188:** Android development (an image and a preset), sessions that move, copy and duplicate
with their state, MCP servers that are reviewed but not published yet built on request, three new start animations,
a better Markdown reader, more servers in the signed MCP catalog - and the fixes of the first complete live check on
a real Arch Linux machine, most of them for `--backend bwrap`.

## Changes in behaviour since 0.1.188

- **Under Bubblewrap, two of Firejail's narrowing options may be left out.** Firejail builds `--protocol` and
  `--restrict-namespaces` with a helper it runs only when root owns it; in Bubblewrap's user namespace the host's
  root is not mapped, so on such hosts the two are left out. sandbox-ai's own system call filter still refuses new
  namespaces and the other socket families, and the run's manifest says why (`firejail.narrowing_left_out`).
- **The app asks before an MCP server is built** through its confirmation settings (the action `mcp-build`, as the
  web interface does), with Cancel as the default button.

## New

- **Android development: the image recipe `android-dev` and the preset `android-development`.** One image on top of
  the `android` variant (adb, apktool, jadx, smali, Frida): JDK 17, the Android SDK in /opt/android-sdk
  (cmdline-tools, platform-tools, platforms and build-tools of API 37, 36 and 35), NDK r30 with CMake, the emulator
  with an x86_64 system image (`android-emulator start [--gui]`, only with `/dev/kvm`), Gradle and Kotlin; every
  download pinned by size, SHA-1 and SHA-256 in `sdk.lock` (a mismatch stops the build), x86_64 only. Building it
  accepts the Android SDK License Agreement (the build says so). The preset opens only Google's Maven, Gradle's and
  Maven Central's hosts, the host's adb server and `/dev/kvm` when there, adds the MCP servers jadx, smali and frida on
  request, and asks before installing on a device or wiping one.
  `sandbox-ai images recipe android-dev --from AGENT && sandbox-ai build android-dev`.
- **A session moves, copies and duplicates with its state.** `sandbox-ai session copy|move NAME HOST` now takes the
  HOME with the agent's session files (the agent resumes its conversation there), the project memory, the
  checkpoints and the run's network approvals (granted there only with `--grant-approvals`, asked) - through
  `session import -` over SSH. A running session is paused for the snapshot (copy thaws it, move stops it here once
  it runs there). `--with-workspace` copies the workspace's files, `--include-secrets` the logins (asked),
  `--config-only` keeps the old behaviour. `session export` writes a manifest with each file's SHA-256; the new
  `session import FILE|-` checks an archive as untrusted input (only folders and plain files, no links, devices or
  `..`, modes cut to the owner's, every file against the manifest, the configuration through the launcher's own dry
  run, folders and secrets it names asked first) and makes a stopped session that `sandbox-ai resume` continues. The
  new `session duplicate NAME NEW` makes a second session here with its own HOME. In the app: Copy/Move with "Its
  state along", Duplicate…, Export with state…, Import…; in the web interface: Duplicate…, Import a session….
- **MCP servers that are reviewed but not published yet are built on request.** A server its catalog has reviewed but
  has no signed image of yet was refused at the start ("no catalog of HOST has it"). Now the CLI (a question on a
  terminal, else the exact command), the app (Board, Start, presets, on this machine or another host) and the web
  interface offer `sandbox-ai mcp add NAME --build`: the catalog's repository at one exact commit (its archive's
  SHA-256 shown), built with Podman as the catalog's CI builds it (base images pinned by digest), smoke-tested with
  sandbox-ai's own run line (its tool list must be the reviewed one), and added **unsigned** - "built here, not
  signed" wherever it shows. Nothing is built without your answer; `--build-plan` shows the plan as JSON. A server
  with a signed image is pulled as before; a catalog whose signature does not hold is never built from.
- **More servers in the signed MCP catalog:** jadx, cfr, frida, time, calculator, arxiv, osv, shodan, wikipedia,
  youtube-transcript and agentql (`sandbox-ai mcp catalog`).
- **Three new start animations in the app:** **Glass cube** (the agent a growing network of light inside a glass
  cube; its one port is the proxy: allowed hosts pass, a tracker bounces off), **Night city** (the agent's requests
  fly as light trails only to the towers you allowed, a new host waits for your answer, a script that takes the decoy
  key trips the canary and the run is paused) and **Vault** (sandbox-ai's layers - seccomp, NoNewPrivs, Firejail's
  namespaces, rootless Podman or Bubblewrap, firewall and proxy - lock around the agent as rings of a vault, each one
  stopping a probe). Settings > Appearance > Intro animation: "A different one at each start" (the default, never the
  same twice in a row), Classic, or one of them; Help > Watch the intro again plays the next. The shared drawing got
  faster too (Classic at 4K: 13.4 ms -> 9.9 ms a frame).
- **The Files page's Markdown reader, with axross-markdown's better ideas** (reviewed in full:
  docs/AXROSS_MARKDOWN_REVIEW.md; not vendored): an SVG whose `<use>` references redraw it over and over is refused
  ("draws too much") instead of holding a CPU core; the link question shows the address as it is sent (a look-alike
  host in punycode, hidden direction marks visible, the link's own text beside it); front matter as a code block,
  GitHub alerts (NOTE, TIP, IMPORTANT, WARNING, CAUTION), math as text with Unicode symbols, the outline marks the
  heading being read, "Copy code block" on a code block's menu.

## Fixes

- **`--backend bwrap` starts again.** On an Arch Linux host (bubblewrap 0.13) every start ended at once - first with
  "/run/firejail/lib/fseccomp is not owned by root, refusing to execute" (see *Changes in behaviour*), then with "the
  connection proxy kept capabilities or can gain privileges: CapInh=000001ffffffffff": switching to its own user
  empties a process's other capability sets but not the inheritable one, which that bubblewrap hands over full. The
  proxy now empties it (and the ambient set) itself.
- **MCP servers with network under Bubblewrap ran without it:** bwrap's `--info-fd` reply spans several lines and only
  the first was read, so the server's network was not set up.
- **Devices added during a run:** `sandbox-ai devices add RUN /dev/dri/renderD128` (any node below a folder a sandbox
  does not have: `/dev/snd/...`, `/dev/bus/usb/...`) failed with "No such file or directory" - the folders above it
  are made now; and `devices remove` failed the same way, because the sandbox's mount namespaces share one `/dev`:
  every one is unmounted first now, the mount point removed after.
- **Plugins attached to a running Claude Code sandbox:** `plugins attach` refused it ("started without the plugin
  store") when the store had marketplaces but no plugin yet - the start makes the store's empty `cache` folder now;
  and `plugins attach --json` printed Claude Code's own "Installing plugin…" line in front of its JSON - that goes to
  stderr now.
- **The live check (`scripts/live_check.sh`):** it sets up its own venv when pytest is a `pip install --user` one
  (hashes checked), makes the parent of its temporary folder, counts Firejail's blacklist stand-in as hidden, checks
  `--untrusted` with a linked credential folder that holds no canary, finds the host's SSH key for remote-mcp in your
  HOME, unloads the models it loaded on the LLM server (before the next model and at the end), and says a model the
  server cannot load (LM Studio: "insufficient system resources") as skipped with that reason.
