# sandbox-ai 0.1.88

Three rounds of performance work on the desktop app, measured offscreen:

- **Board:** a change of a part's properties updates the parts where they are instead of making the whole scene
  again; parts whose texts did not change are not laid out again; the grid of dots is drawn into a cache.
  8 parts, 40 changes and 10 steps of Undo: 1.18 s -> 0.44 s.
- **Log window:** each line is made once, its colours once per theme; text is checked for control characters only
  where there are any (`printable_text`, used everywhere in the app). 2000 entries with filter and level:
  1.24 s -> 0.52 s.
- **State:** the app's state file is written by a thread of its own - a slow or busy disk never holds the window -
  and every private JSON file is written in one go and synced to the disk before it replaces the old one (a crash
  or a power loss leaves the old file or the new one, never an empty or a cut one).
- **(?) marks:** drawn from a picture made once per look and theme instead of at every repaint; the event loop's
  longest pause while idle 63 ms -> 49 ms.
