# sandbox-ai 0.1.241

**What came since 0.1.188:** a start that offers what it lacks instead of only refusing, build toolchains mounted
into a sandbox, every agent as one of Cairn's workers, Board and Start as one page, an LLM server for all hosts, MCP
servers without folders to type (and built on request when their catalog has reviewed them but not published them
yet), sessions that move, copy and duplicate with their state, Android development (an image and a preset), presets
that propose a bridge, an app that tells you when a signed update is there, a readable Help with reading fonts, three
new start animations, a better Markdown reader, more servers in the signed MCP catalog - and the fixes of the first
complete live check on a real Arch Linux machine (most of them for `--backend bwrap`), of two security reviews and of
walking the user's journeys end to end.

## Changes in behaviour since 0.1.188

- **A start offers what it lacks instead of only refusing.** On a terminal it lists everything missing - an
  image to build, an MCP server to add (with its default folders), a toolchain, an identity or kit - with the
  command for each and asks once ("Yes, all / choose / no"); `sandbox-ai defaults set fix_questions each` asks per
  item. Without a terminal it refuses as before and ends with the commands to copy. `--fix` does what the start
  needs without asking, `--fix-only ID` exactly the named fixes, `--fix-plan` prints the plan as JSON. In the modes
  high and paranoid nothing unsigned or network-opening is offered. Every secret a start reads is asked on a
  terminal (never shown); a missing VPN profile can become a Tor profile (your choice, never taken by `--fix`);
  `--service` images of sandbox-ai's own are built, gone ones pulled again by digest; Bubblewrap without the
  agent's program offers `--backend podman`; `resume`, `mcp attach` and `toolchain attach` offer what they lack;
  what needs root (sshfs, a udev rule, subuid ranges) is shown with its command. The app's one question also holds
  a plain start's missing image and offers `hosts update` for a host too old; the Board applies a chosen way to
  start to its parts. Where there are two ways to start (an agent
  named that is not in the session) it asks which, never `--fix`. `doctor` ends with the same commands. The app
  (Settings > Polling: what a start lacks) and the web page ask the same.
- **Cairn and the browser need no catatonit on the host:** their containers bring their own init; an MCP image or
  service gets Podman's `--init` only where the host has it (else refused before the start, with the package to
  install, unless it brings an init of its own); `doctor` checks "Podman init".
- **A model's traffic light comes only from runs with that agent.** A model verified in Claude Code is grey in
  OpenCode until OpenCode was measured with it ("no data yet in OpenCode"), in the CLI, the start's note, the web
  page and the app; a model's own light is the best of its measured agents. Five statuses that had no run behind
  them are grey now: Qwen3-Coder-30B in Codex and in Claude Code, Nemotron MLX in Claude Code (only API probes),
  Qwen3.8-27B in every agent but Claude Code (partly working there, measured), VCoder-120B.
- **Under Bubblewrap, two of Firejail's narrowing options may be left out.** Firejail builds `--protocol` and
  `--restrict-namespaces` with a helper it runs only when root owns it; in Bubblewrap's user namespace the host's
  root is not mapped, so on such hosts the two are left out. sandbox-ai's own system call filter still refuses new
  namespaces and the other socket families, and the run's manifest says why (`firejail.narrowing_left_out`).
- **The app asks before an MCP server is built** through its confirmation settings (the action `mcp-build`, as the
  web interface does), with Cancel as the default button.
- **No more "not live-tested yet".** The nine newer agents (Hermes, Qwen Code, dsh, Goose, OpenHands, nanobot,
  Letta, OpenCode 2, pi), `--nested-containers` and their presets no longer carry the note or badge: at a start, in
  `presets list`/`show`, on the web page, in the app's gallery, Board and wizard, and in Help and the READMEs. Their
  dry runs no longer contain `"experimental": true`.

## New

- **Uninstall on another host:** `sandbox-ai hosts uninstall NAME` (the app's Hosts page: Uninstall…, the web page
  the same) shows that host's own table of what goes and asks first; `--installation user|system` picks the copy -
  remove your own so only the system-wide one is left - and `--purge`, `--secrets`, `--mcp-data` are choices.
- **Older toolchain versions:** the signed catalog has jdk 17 and 11, node 24 and 22, python 3.13, 3.12 and 3.11, go
  1.26 and rust 1.98 and 1.97 beside the newest. `--toolchain jdk@17` (or the exact version) picks one, a bare name the
  newest; the store keeps several side by side, a sandbox gets one version of each. `toolchain list` and `catalog`
  show what to type for each, the Board's field and Add toolchain… offer every version.
- **Presets for the languages, with their toolchain:** `rust`, `go`, `jvm`, `dotnet`, `data-ml` and `development`
  bring theirs (`--toolchain`; a start offers `toolchain add` when the store lacks it), and `node`, `python`,
  `c-cpp` (Clang via Zig, CMake, Ninja) and `zig` are new.
- **Shorter right-click menu on Sandboxes & sessions:** what adds something to a running start or takes it out again
  is under Add… and Remove…, each opening the kinds (MCP server, skills/plugins, toolchain, workspace, device); a
  terminal tab's While it runs the same.
- **The Board arranges and centres itself** whenever it is shown or a board arrives (new, a preset, a file, a
  project, another host), without a step of the Undo history.
- **German:** the limits of memory, CPUs and processes are "Hardware-Limits".
- **`sandbox-ai mcp update [NAME...]`:** an MCP server takes its catalog's newer image - the catalog's signature
  checked again, its folders, variables, limits, network and VPN kept, asked first (`--yes`, `--check` only lists).
  `mcp list`, `mcp show`, `doctor` and a start say when a newer signed image exists; the app's MCP servers page and
  the web page have Update and Update all.
- **Live check `mcp-live`:** every server of the signed catalog added with its defaults and used the way an agent
  uses it - started for a start, through its relay: handshake, tools, the smoke calls - with Podman and Bubblewrap,
  and a second project to check one project's server never sees another's files
  (`scripts/live_check.sh --only mcp-live [--mcp-servers binwalk,radare2]`).
- **ARTEX, an agent for authorized penetration tests, beside the agent** (`--artex`): reviewed for backdoors first
  (none found in the source; prebuilt images and release zips of ARTEX are never used), built by sandbox-ai from the
  pinned commit of RuoJi6/ARTEX v0.3.15 with its self-update compiled out; its console listens on 127.0.0.1 only and
  is forwarded to this computer, its admin password is set by sandbox-ai before the console can be reached
  (`sandbox-ai artex console` shows it), its model is the sandbox's (`--llm` or the provider through the proxy), and
  it reaches only the targets the allow-list opens. The preset `artex-pentest` asks for the target and opens exactly
  its ports; the mode paranoid refuses `--artex`. On the Board: the part ARTEX.
- **Every agent can be one of Cairn's workers.** `--cairn-workers` takes every harness (`AGENT=MODEL` where the
  harness has a model option); Cairn itself is unchanged: sandbox-ai's relay turns its driver call into that
  harness's own one-shot run. Without `--cairn-workers` every agent of the session works, best supported first.
  `sandbox-ai cairn workers` shows each harness's traffic light with its evidence, so do the start's notes, the dry
  run and the Board's worker field; a harness that does not work is refused with the reason and the command for
  another. Claude Code is partly working (CI job agents-live (cairn)); the others have no data yet until
  `scripts/live_check.sh --only cairn-workers-live --llm NAME` ran.
- **The tours follow the app as it is now:** steps for toolchains, the Kill switch, MCP copy in both directions, LLM
  servers for all hosts, starting from and saving presets on the Board; every page's tour names the buttons its
  Help names, Help's screenshots and the video storyboard use the same names. A test fails when a tour points at a
  control that is gone or hidden.
- **Live check `presets-live`:** `scripts/live_check.sh --only presets-live --llm NAME` starts every built-in
  preset for real (its MCP servers and services must come up) and writes a row per preset;
  `scripts/import_live_report.py REPORT.json` turns a report into `sandbox/live_evidence.json`, and the presets show
  their last live result (green with date and version, red with the reason) in `presets list`, the web page and the
  app.
- **MCP servers are added without folders to type.** `sandbox-ai mcp add NAME` works for every catalog server:
  its `/work` is the workspace of the start that uses it (one server per workspace, so one project's files never
  reach another project's agent), every other folder it keeps gets a folder of its own under sandbox-ai's data
  (`mcp show NAME` names it). `--mount TARGET=HOST` still wins; `--mount TARGET=default` goes back. The add forms
  of the app and the web page label each field "Folder on HOST for the container's TARGET". Every server image has
  `/work`, `/work_ro`, `/work_rw`, `/app` and `/srv` (the MCP catalog of 2026-11-22).
- **Copy an MCP server to another host:** "Copy NAME to another host…" on the MCP servers page and in its
  right-click menu; Copy runs the check itself.
- **Login tabs close themselves** 30 s after a successful `sandbox-ai login` ("Keep it open" stops it); a failed
  login stays open.
- **An LLM server for all hosts.** `sandbox-ai llm share NAME` copies a registered model server to every host of
  `sandbox-ai hosts`, so a start there can use `--llm NAME` too; its key goes only to the hosts you name
  (`--key-to ct1,ct2`), sent into that host's secret store, never on a command line or in a log. Changes here
  (`llm set`, `llm add --replace`, `llm remove`) and `hosts add/update/remove` keep the copies in sync; a host that
  does not answer is tried again later, `llm sync` at once. `llm unshare NAME` removes the copies and the keys sent.
  A server on this machine's loopback is not shared (127.0.0.1 there is that host). In the app: the column and
  button For all hosts on the LLM servers page; on the web page the same. The other host needs this version.
- **Board and Start are one page.** The navigation has one entry, Start, with a switch above it: Board (the
  default) or Expert. Expert is the old start form plus the whole command line as an editable field; both are the
  same start at every moment: typing `sandbox-ai codex --memory 4g -w ~/proj --name night` changes the board, moving a
  part changes the line. A line that cannot be read changes nothing and says why; a value the launcher refuses is
  said below the line. Options no part shows (`--mode`, `--name`, canaries, checkpoints) sit on a new part, Other
  options. One Undo history for both views; F6 switches, Ctrl+1 opens Start in the view chosen last (Ctrl+2 still
  the Board view). Resume with… has "On the Start page…".
- **Android development: the image recipe `android-dev` and the preset `android-development`.** One image on top of
  the `android` variant (adb, apktool, jadx, smali, Frida): JDK 17, the Android SDK in /opt/android-sdk
  (cmdline-tools, platform-tools, platforms and build-tools of API 37, 36 and 35), NDK r30 with CMake, the emulator
  with an x86_64 system image (`android-emulator start [--gui]`, only with `/dev/kvm`), Gradle and Kotlin; every
  download pinned in `sdk.lock` (a mismatch stops the build), x86_64 only: Google's archives by size and Google's
  own SHA-1 (Google publishes no SHA-256: the first build prints the one it computed, "unconfirmed SHA-256", to be
  written into `sdk.lock`), Gradle and Kotlin by their publishers' SHA-256. Building it
  accepts the Android SDK License Agreement (the build says so). The preset opens only Google's Maven, Gradle's and
  Maven Central's hosts, the host's adb server and `/dev/kvm` when there, adds the MCP servers jadx, smali and frida on
  request, and asks before installing on a device or wiping one.
  `sandbox-ai images recipe android-dev --from AGENT && sandbox-ai build android-dev`.
- **A session moves, copies and duplicates with its state.** `sandbox-ai session copy|move NAME HOST` now takes the
  HOME with the agent's session files (the agent resumes its conversation there), the project memory, the
  checkpoints and the run's network approvals (granted there only with `--grant-approvals`, asked) - through
  `session import -` over SSH. A running session is paused for the snapshot (copy thaws it, move stops it here once
  it runs there). `--with-workspace` copies the workspace's files, `--include-secrets` the logins (asked),
  `--config-only` keeps the old behaviour. `session export` writes a manifest with each file's SHA-256; the new
  `session import FILE|-` checks an archive as untrusted input (only folders and plain files, no links, devices or
  `..`, modes cut to the owner's, every file against the manifest, the configuration through the launcher's own dry
  run, folders and secrets it names asked first) and makes a stopped session that `sandbox-ai resume` continues. The
  new `session duplicate NAME NEW` makes a second session here with its own HOME. In the app: Copy/Move with "Its
  state along", Duplicate…, Export with state…, Import…; in the web interface: Duplicate…, Import a session….
- **MCP servers that are reviewed but not published yet are built on request.** A server its catalog has reviewed but
  has no signed image of yet was refused at the start ("no catalog of HOST has it"). Now the CLI (a question on a
  terminal, else the exact command), the app (Board, Start, presets, on this machine or another host) and the web
  interface offer `sandbox-ai mcp add NAME --build`: the catalog's repository at one exact commit (its archive's
  SHA-256 shown), built with Podman as the catalog's CI builds it (base images pinned by digest), smoke-tested with
  sandbox-ai's own run line (its tool list must be the reviewed one), and added **unsigned** - "built here, not
  signed" wherever it shows. Nothing is built without your answer; `--build-plan` shows the plan as JSON. A server
  with a signed image is pulled as before; a catalog whose signature does not hold is never built from.
- **Build toolchains, mounted into a sandbox** (first round: go, python with uv, jdk with Maven/Gradle/Kotlin, zig,
  cc, node with TypeScript, dotnet, rust). Each is a signed archive of sandbox-ai-mcp's toolchains catalog, checked
  and unpacked into a store, and mounted read-only at `/opt/toolchains/NAME`: at the start (`--toolchain go`) or
  into a running sandbox (`sandbox-ai toolchain attach RUN go`, `detach`), on the agent's PATH, with its package
  registries opened as the language presets open them (not in the modes high and paranoid). A host below a
  toolchain's glibc floor or without the libraries it names is refused with the reason. In the app: a Toolchains
  part on the Board, Add/Remove toolchain… on the Sandboxes page, its right-click menu and a terminal tab's menu; in
  the web interface the same.
- **Presets with a bridge.** A preset may propose a session bridge for its start: the peer is chosen when it starts
  (never fixed in the preset), and the bridge is made only after the start runs and you confirm it with its warnings
  - on the terminal (`bridge this start (rev) to web with ask,files:ro:src? [y/N]`), as a Bridge part on the app's
  Board, or in the web interface's start form. New presets `pair-reviewer` (a reviewer that may ask the coder session
  and read its code read-only) and `docs-from-code` (a docs writer that reads the code session read-only); `observer`
  uses it too. A project file never carries one.
- **The app tells you about a signed update.** It checks every hour whether the day's check is due (not only at its
  start), shows "sandbox-ai X is available" in the status line and in Settings > Updates, and sends one notification
  per version with Update now…. Only a release whose `SHA256SUMS` carries a good signature of a trusted key is
  offered; a bad or missing signature is said and never offered. A check that fails says why (offline, GitHub's rate
  limit, no signature). `sandbox-ai update --check` on a git checkout reports the newest release instead of refusing.
- **More servers in the signed MCP catalog:** jadx, cfr, smali, frida, time, calculator, arxiv, osv, shodan,
  wikipedia, youtube-transcript, agentql and axross (`sandbox-ai mcp catalog`).
- **Three new start animations in the app:** **Glass cube** (the agent a growing network of light inside a glass
  cube; its one port is the proxy: allowed hosts pass, a tracker bounces off), **Night city** (the agent's requests
  fly as light trails only to the towers you allowed, a new host waits for your answer, a script that takes the decoy
  key trips the canary and the run is paused) and **Vault** (sandbox-ai's layers - seccomp, NoNewPrivs, Firejail's
  namespaces, rootless Podman or Bubblewrap, firewall and proxy - lock around the agent as rings of a vault, each one
  stopping a probe). Settings > Appearance > Intro animation: "A different one at each start" (the default, never the
  same twice in a row), Classic, or one of them; Help > Watch the intro again plays the next. All four, Classic
  too, draw their frames faster (captions, title and still parts from cached pixmaps).
- **Help, readable and in one pattern.** Every section of the app's Help starts with one sentence of what it is
  for, a screenshot of its page taken from the running window with numbered arrows at the real controls and "Show
  me" beside each (the control is outlined for a few seconds), "How do I…" in short numbered steps with every
  command a block to copy, and the details folded below. Its text is set in Atkinson Hyperlegible Next (Mono for
  commands), larger and in a narrow column, its colours readable in every theme. Settings > Appearance > Reading
  font puts Atkinson Hyperlegible, OpenDyslexic or Lexend on all of the app's text (terminals and code keep their
  font); the fonts come with sandbox-ai, pinned and checked by SHA-256. The web interface's help follows the same
  pattern and its Fonts panel offers the same reading fonts.
- **The Files page's Markdown reader, with axross-markdown's better ideas** (reviewed in full:
  docs/AXROSS_MARKDOWN_REVIEW.md; not vendored): an SVG whose `<use>` references redraw it over and over is refused
  ("draws too much") instead of holding a CPU core; the link question shows the address as it is sent (a look-alike
  host in punycode, hidden direction marks visible, the link's own text beside it); front matter as a code block,
  GitHub alerts (NOTE, TIP, IMPORTANT, WARNING, CAUTION), math as text with Unicode symbols, the outline marks the
  heading being read, "Copy code block" on a code block's menu.

- **Live check `harnesses-live`:** `scripts/live_check.sh --llm NAME` (or `--only harnesses-live`) starts every
  harness of the launcher through the real launcher with your model server, once under Podman and once under
  Bubblewrap; each writes a file with its own tool and answers with a nonce. A missing image is built first and its
  build time recorded; the report has one row per harness. A whole run includes it when a model server is set up,
  and asks first.

## Fixes

- **A Tor profile whose first bootstrap stalls comes up on the second try:** the stalled tor runs as its own user,
  which the container's root may not signal, so it kept its port and the retry failed; it is now ended through its
  own user first.
- **Input dialogs are never narrower than their title** (German "Hardware-Limits von …" was cut).
- **After `hosts update` the version is shown at once** (it was emptied), and this machine's own row shows its
  version.
- **A host with two installations** (your own in `~/.local/bin` and a system-wide one): every command runs the copy a
  terminal there runs, `hosts list` names both and warns when they differ, and `hosts update --installation` picks
  which. After an update the app forgets the host's old options, so a start with a new option (`--toolchain`) is no
  longer refused by an old list.
- **Every preset works on a fresh install:** a start gives a plan with what it offers (image, MCP servers, toolchains)
  or names the values only you can give - checked for every preset and agent. `firmware-iot`, `hardware-analysis` and
  `software-analysis` offered nothing where axross's hub has servers of the same names: their catalog's server is
  offered now.
- **A start on another host whose sandbox-ai is older** than an option it uses (`--toolchain`) is said as that host
  being too old, with the update to do, instead of argparse's usage.
- **The Board's Toolchains field shows that it is a list:** "Choose from the list, or type: NAME[@VERSION]", and a click
  into the empty field opens the store's and the catalog's toolchains (Add, then the next).
- **MCP servers under Bubblewrap start where the caller's environment does not name the user bus** (from the app, a live check): `systemd-run` for their limits is told where it is, instead of ending with "Failed to connect to user scope bus".
- **The app no longer crashes on a right click in a list** (a segfault in a context menu: the model drop-downs'
  sort by traffic light left stale item wrappers, and a new menu entry at a reused address came back as one of them).
  No item wrapper is kept any more; a test reproduces the crash and a guard keeps the pattern out.
- **`scripts/live_check.sh --only mcp-live` adds the signed catalog's servers by their prefix** (`mcp:binwalk`): with
  axross's hub installed too, a bare name was ambiguous and every server failed at once.
- **MCP servers no longer end before they answer on hosts without a systemd user session** (an SSH login without
  lingering) or without delegated memory/pids controllers: rootless Podman refused every connection's container
  for its limits. A server's container now asks only for the limits the host can enforce (the start says which are
  not), and a server that still ends before it answers says Podman's own error.
- **`scripts/live_check.sh` with `--llm` no longer ends in `NameError: name 'model_found' is not defined`.**
- **Security review round 3** (each finding with its test):
  - **high:** the proxy added your Git login to any POST whose path ended in `/git-upload-pack` - also to a
    Gitea/Forgejo contents API call that commits a file of that name, unseen by the push check. A Git login now goes
    only to Git's own transport (its `info/refs` and its content types), never to a forge's REST API;
  - Git LFS uploads (`git lfs` sends the files before the push is checked) are asked while the privacy check is on,
    refused with `--ask off`; downloads go on;
  - `--publish github/gitlab` asks for GraphQL commits, GitLab projects named by their path, GitHub Enterprise's
    API paths and changes of a repository's visibility;
  - DNS queries with more than one question, compression pointers or extra records are refused, every name in them
    searched for canaries;
  - `--no-inspect` says at the start that a CDN routes by the name inside, which sandbox-ai cannot see;
  - `board import` names each secret of yours the bundle's start would hand on, and to which host.
  - after `sandbox-ai net allow RUN --dns` only the DNS stub's own packets reach the nameservers: the agent querying
    them directly skipped the stub's log and canary search (an answer too large for UDP is no longer retried over
    TCP during the run; `--dns` at the start is unchanged);
  - `hosts run` sends every command to `/bin/sh` in a form every login shell reads alike (fish and csh read the
    old quoting differently);
  - a preset from an extra directory warns at the start, in `presets show/list` and on the Board which secrets it
    hands on and where, and when it takes a built-in preset's place;
  - plugin hooks run from a copy made at the start and checked against their approval, never from the live store.
- **Pressing Start in the app never waits on Podman:** the Board and Expert views check the agent's image in the
  background as soon as they show it; a macOS notification no longer starts osascript on the window's thread.
- **The Files page's SFTP connections no longer leave a thread behind** each when they close.
- **Every dialog has a default button** (Enter): Properties' Apply, New from preset's Create; a message box's
  hidden "Show details…" never takes it. German: a kept secret or key is "gespeichert" everywhere.
- **Security review of the boundary itself** (each finding with its test):
  - **high:** a chunked request's trailer could carry a second request that the proxy never checked (a server
    reading a bare line feed as a line end saw it as the agent's own request: past the rules, the push check, the
    package guard, approvals and the canary block), and chunk extensions and trailer fields were never searched for
    canaries and secrets. Requests now go out as bare chunks: extensions and trailer fields are dropped;
  - building an MCP server from a local catalog checkout no longer runs that repository's own git hooks or filters
    on the host;
  - a canary sent to the model provider's address with a Host header naming another site is refused, not only
    reported;
  - HTTP/1.0 with `Transfer-Encoding` and a `Content-Length` beyond 2^63-1 are refused.
- **An installation newer than the newest release says "nothing to update"** - the CLI, `install.sh`, the
  packages (pyz, AppImage, macOS app, pip), the app, the web interface and `hosts list` (`install.sh` failed with
  "an old release served again?"). A replay is still refused, now per source: a release of your local Gitea is no
  reason to distrust GitHub's older one. `install.sh` run through an installation's own `sandbox-ai-update` acts
  on that installation; an update or `--force` stopped half way no longer leaves the installation without its
  tree (the new one is swapped in by renames); a download that was refused is fetched anew, not taken again;
  `hosts list` offers a host's update only for a release signed by a key that host trusts.
- **Starting a newer app while an older one is still busy** (it has just started) no longer leaves the older one
  running: the newer start asks it again for up to 10 s before it takes over.
- **The MCP servers page fits a narrow window in German** (its buttons wrap); a toolchain's refusal in the app keeps
  its line breaks; the list of Cairn workers no longer flashes up as a window of its own; four settings readers
  survive a deeply nested damaged file.
- **Found walking the user's journeys end to end:**
  - a start with binwalk no longer warns that its own `/out` lies in sandbox-ai's folder (a folder you choose
    there still is, and a link planted in its place is never exempt);
  - `mcp add NAME` of a server in several catalogs gives the command for each and whose catalog it is;
  - `mcp copy`'s plan, the app's copy dialog and the web form say "the start's workspace" and "its default folder
    there" instead of `@workspace` and raw JSON;
  - `mcp attach --help` names `kits restart-agent` for Codex and Claude Code, not `resume --restart`;
  - `--mcp mcp:calculator` (a catalog id) is refused before anything is built, with `--mcp calculator`;
  - a missing VPN profile is one item of the fix plan with both ways under it;
  - paranoid offers to add an MCP server that has no network (one with network stays refused);
  - `toolchain catalog` names the toolchains an entry requires, `toolchain add cc` says it brings zig before it
    downloads;
  - `toolchain --help` and `cairn workers` are short (details: `cairn workers AGENT`);
  - help texts write `sandbox-ai` in lower case everywhere; `live_check.sh --list` keeps a check's timeout apart
    from why it exists.
- **Security review of this release's new parts and the hardening after it** (each finding with its test):
  - a toolchain's registries now follow the administrator's policy (`allow_within`, forbidden `--allow-host` or
    presets, shared wildcards): what it does not take stays closed, the toolchain is mounted all the same;
  - an MCP server bound to the start's workspace keeps its other folders (`/out` ...) per workspace too, so one
    project's extracted files never reach another project's agent;
  - `llm share` sends a key only to the machine it was given to: a host removed from `sandbox-ai hosts` leaves the
    list of key receivers, and a name that now points to another address gets the entry but no key until named
    again;
  - a session keeps none of `-fx`, `-fo`, `-fp` (the short forms of the fix options);
  - `mcp copy` from another host caps each copied folder to the mode its catalog entry declares and binds the
    start's workspace unasked only where that is the default here (the plan says what was capped);
  - re-pulling an MCP image that is gone says where it came from: unsigned and project-file servers are marked
    UNSIGNED, and in high and paranoid only shown;
  - a toolchain entry may set no variable that steers other code (`LD_*`, `PYTHON*`, `NODE_*`, `BASH_ENV`, `GIT_*`,
    proxies, the agents' and sandbox-ai's own): such an entry is refused, one already in the store is marked and
    refused at a start;
  - `--mcp-env` also warns about `LOCPATH`, `GLIBC_TUNABLES`, `NLSPATH` and `MALLOC_CONF`;
  - the LLM servers page's For all hosts dialog shows a host's name in its key tooltip as text, never as markup.
- **The Board no longer asks for an MCP server's folder** where the host has the folder defaults; it asks only for
  a folder a start names but leaves empty, or on a host whose sandbox-ai is older.
- **`mcp copy --drop-path`:** a dropped folder gets its default on the other host (`/work` the start's workspace,
  any other a new empty folder of its own there), and the plan says so.
- **Help: "Videos about this page" reaches the real window again** (the redesign drew the sections past it).
- **The app's canary log no longer times out:** reading it is linear in the records (30 runs with 300,000 activity
  records: 3 min 51 s before, 10.6 s now).
- **Adding an MCP server to a running Codex no longer ends the sandbox** (exit status 143): Codex restarts inside
  its sandbox with the new server. An agent that cannot (OpenCode and others read their servers only at the start)
  says so first and offers the restart that keeps the session.
- **Copy to another host was always greyed out, Check worked only sometimes:** a late answer of an older check
  replaced the newer one's; now only the newest counts.
- **`uninstall --purge` keeps the MCP servers' own folders** (a memory server's graph); `--purge --mcp-data`
  removes them too.
- **`mcp add --mount` says which side is which** when the folder given for this machine is one of a container's
  usual folders (`--mount /work=/app:rw`): the right side is a folder of this machine, the left one the folder in
  the server's container, with the command that fills the container's `/app`.
- **`--backend bwrap` starts again.** On an Arch Linux host (bubblewrap 0.13) every start ended at once - first with
  "/run/firejail/lib/fseccomp is not owned by root, refusing to execute" (see *Changes in behaviour*), then with "the
  connection proxy kept capabilities or can gain privileges: CapInh=000001ffffffffff": switching to its own user
  empties a process's other capability sets but not the inheritable one, which that bubblewrap hands over full. The
  proxy now empties it (and the ambient set) itself.
- **MCP servers with network under Bubblewrap did not start.** bwrap's `--info-fd` reply spans several lines and
  only the first was read; and loading the server's egress rules failed ("setns(CLONE_NEWNET): Operation not
  permitted"): bwrap moves the server into a second, nested user namespace, and the network namespace belongs to the
  first. sandbox-ai now enters the user namespace that owns the network namespace, and slirp4netns is pointed at a
  short-lived anchor process there (its own path mode leaves its sandboxing parent outside: "setegid(0)"). A server
  whose network does not come up is refused instead of started without one. Found by the MCP catalog's CI.
- **A catalog entry may give its server a /tmp that runs programs** (`"tmp_exec": true`, signed with the entry; every
  other server keeps a `noexec` /tmp under Podman): smali's apktool needs it for aapt2.
- **Devices added during a run:** `sandbox-ai devices add RUN /dev/dri/renderD128` (any node below a folder a sandbox
  does not have: `/dev/snd/...`, `/dev/bus/usb/...`) failed with "No such file or directory" - the folders above it
  are made now; and `devices remove` failed the same way, because the sandbox's mount namespaces share one `/dev`:
  every one is unmounted first now, the mount point removed after.
- **Plugins attached to a running Claude Code sandbox:** `plugins attach` refused it ("started without the plugin
  store") when the store had marketplaces but no plugin yet - the start makes the store's empty `cache` folder now;
  and `plugins attach --json` printed Claude Code's own "Installing plugin…" line in front of its JSON - that goes to
  stderr now.
- **The sandbox-ai skill is the same for every agent** (Claude Code, Codex, OpenCode, OpenCode 2, Goose, Hermes,
  Qwen, Pi, Letta, DSH, nanobot, OpenHands): generated from one source with each agent's own facts, and extended
  with what came lately - sessions moved and copied with their state, bridges (and which agents take one while they
  run), MCP servers built on request, devices added live, signed updates. Every `sandbox-ai` command in it is checked
  against the real command line.
- **Model drop-downs list the verified models first:** by their traffic light - green, yellow, red, grey (no
  data yet), then models without one. Where the agent is already chosen (the Board, the wizard, a preset), the light
  is that agent's: a model verified in Claude Code but only partly working in OpenCode shows yellow for OpenCode,
  and its tooltip says so ("In OpenCode: partly working"), the other agents named after.
- **Scrolling a window no longer changes its drop-down lists.** The mouse wheel over a combo box, a number field or a
  slider that you have not clicked scrolls the page or dialog it lies in; a click activates it, and then the wheel is
  its own (an open list scrolls as always).
- **The app's videos open where you see them.** The video windows had no parent, so on a tiling window manager
  with the main window full screen they opened behind it; they stay above the main window now. A release that is
  not published yet offers the newest published one's videos (checked the same way, signed), and a failure (offline,
  no videos in the release, a bad signature) is said in red instead of a grey line.
- **The Approvals page no longer fails every second** with "RecursionError ... QTableWidgetItem::__lt__" (PySide6
  6.12): sorting a cell without a sort value called back into itself.
- **A refusal no rule made is said as what it is**, not as "rule None in the ruleset None refuses it": "too many
  questions" (20 open at once or 500 in a run) now says how to allow it during the run.
- **"Check for updates" in the app did nothing you could see** outside the System page, and nothing at all while a
  check still ran: a check you click now answers in the status bar wherever you are - that it runs, what it found,
  why it failed, or that one still runs.
- **"New bridge…" in the app did nothing** with fewer than two sessions running: the button was disabled and only its
  tooltip said why. It always answers a click now - how many sessions run and what a bridge needs, a wait while the
  page still reads the sessions, an error shown instead of only logged - and the box says what it does while a bridge
  is checked and made. A host that answers garbage is named as that host's problem.
- **The live check (`scripts/live_check.sh`):** it sets up its own venv when pytest is a `pip install --user` one
  (hashes checked), makes the parent of its temporary folder, counts Firejail's blacklist stand-in as hidden, checks
  `--untrusted` with a linked credential folder that holds no canary, finds the host's SSH key for remote-mcp in your
  HOME, unloads the models it loaded on the LLM server (before the next model and at the end), and says a model the
  server cannot load (LM Studio: "insufficient system resources") as skipped with that reason. New checks:
  `bridge-live` (two real sessions bridged, and the same bridge made through the app) and `update-live` (the newest
  GitHub release's signature and what an installation is offered).

## Known limits

- **ARTEX's image is built on your machine** (`sandbox-ai build artex`), from the pinned source; its server was compiled
  and checked here, the whole image build and a live start are what `scripts/live_check.sh --only artex-live` shows.
- **Checked only on a real host, by the live check you run** (`scripts/live_check.sh --list` names them; each asks
  first and writes a row of its report): `harnesses-live` (every harness against your model server, under Podman and
  Bubblewrap), `presets-live` (every built-in preset started for real; until a report is imported with
  `scripts/import_live_report.py`, the presets show no live result), `cairn-workers-live` (until it ran, every
  Cairn worker but Claude Code is grey, "no data yet"), `toolchain-live` (toolchains attached to a running session
  and a start with `--toolchain`), `bridge-live` and `update-live`. This release's tests run the rest with stand-ins
  for Podman, Bubblewrap and the model server.
- **Android:** Google publishes no SHA-256 for its SDK archives: until a first build has printed them, 13 of the 15
  downloads in `sdk.lock` are checked by size and Google's SHA-1 only.
- **macOS:** the update of `sandbox-ai.app` from the disk image is the one path no test runs on a real Mac (the
  tests' `hdiutil` is a stand-in); the app is not notarised.
