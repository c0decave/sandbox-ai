# sandbox-ai 0.1.78

0.1.78 carries everything listed for 0.1.77 (that release never reached GitHub or PyPI: its macOS install check
failed), and on top:

- **Workspaces, devices and limits from the app and the web:** the app's "While it runs" box adds a workspace
  (read-only, or writable after a confirmation) and removes one (a busy one is detached only after asking), and
  lists the workspaces added during the run. The web interface has a Resources card for every running start, on
  any host: its workspaces, devices and resource limits, with a writable workspace, a device or a forced removal
  confirmed first (the server refuses them without).
- **Pushes from a workspace added during the run:** the push check takes its commits, with the run's rules and
  its project's own privacy rules (`push-added.json` beside the run's `push.json`, written on the host); the
  privacy check after the run looks at the writable ones too. Before, such pushes to a public remote were refused.
- **Each start workspace with its own project's rules** in the push check, read-only ones included (a mix of
  read-only and writable workspaces could pair a workspace with another project's rules).
- **Host wildcards in the app:** the Allow dialog explains `*.DOMAIN`.
- **Releases:** a failed check of a package is shown as an annotation on the job (readable through the API); a
  manual release run can skip the test suite (`gh workflow run release.yml -f quick=true`; a tag always runs it).
- **Approvals for the front ends:** `sandbox-ai approvals list --json` carries each question's `timeout`, its
  `seconds_left` (computed on its own host, so another machine's clock does not matter), the widest scope an
  allow keeps (`max_scope`) and a browser question's URL.
- **One SSH connection per host:** commands to another host share one connection for a minute (a master started
  on its own, its socket in a private folder of `XDG_RUNTIME_DIR`); the app and the web poll other hosts without
  a handshake each time. `SANDBOX_AI_SSH_MULTIPLEX=0` switches it off.
- **The macOS app starts again:** its launcher read a variable before setting it (and stopped under `set -u`);
  both launchers are now tested under `sh -eu`. The macOS disk images pass their install check on arm64 and
  x86_64.
- **Web: approvals of every host on one page.** The badge, the tab title and a countdown per question (amber, red,
  expired) cover all hosts at once; answers go to the question's own host; a host that cannot be reached says so
  instead of showing 0. A browser question shows its link, opened where you are ("Opened it — allow"). Deny holds
  for the run; "Block always" asks first.
- **Web: one rule for confirmations.** Stop, delete, removing a limit, blocking always and lowering a host's
  defaults (mode lax/low, telemetry on, canaries off) are confirmed in the page, naming host and start, and the
  server refuses them without. A stopped kept start shows what changed in its HOME before it resumes.
- **Web: the rest.** Open terminals survive page changes; start options are split like a shell line (`-m sonnet`);
  MCP rows offer only what applies to them; the starts page refreshes itself; `net show` is a table with Revoke
  per row; the page is kept in the address (reload, Back); screen readers hear toasts and the approvals count
  only.
- **Workspaces:** `/proc`, `/sys` and `/dev` are refused as workspaces (at a start and live, read-only too), and a
  live add checks the file system of every mount it would bring in; no live add without `mount_setattr`
  (Linux 5.12); a removal that fails half-way puts the workspace back where it was taken away; `workspace remove`
  tells a name from a directory and refuses an ambiguous one.
- **Limits:** on Podman `sandbox-ai limits` changes the container's own limits (before: the pod's, which did not
  bind); `sandbox-ai limits RUN --show [--json]` shows the current ones; the memory watch follows the smallest
  limit above the sandbox and puts back a `memory.high` that systemd reset.
