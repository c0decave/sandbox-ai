# sandbox-ai 0.1.78

0.1.78 carries everything listed for 0.1.77 (that release never reached GitHub or PyPI: its macOS install check
failed), and on top:

- **Workspaces, devices and limits from the app and the web:** the app's "While it runs" box adds a workspace
  (read-only, or writable after a confirmation) and removes one (a busy one is detached only after asking), and
  lists the workspaces added during the run. The web interface has a Resources card for every running start, on
  any host: its workspaces, devices and resource limits, with a writable workspace, a device or a forced removal
  confirmed first (the server refuses them without).
- **Pushes from a workspace added during the run:** the push check takes its commits, with the run's rules and
  its project's own privacy rules (`push-added.json` beside the run's `push.json`, written on the host); the
  privacy check after the run looks at the writable ones too. Before, such pushes to a public remote were refused.
- **Each start workspace with its own project's rules** in the push check, read-only ones included (a mix of
  read-only and writable workspaces could pair a workspace with another project's rules).
- **Host wildcards in the app:** the Allow dialog explains `*.DOMAIN`.
- **Releases:** a failed check of a package is shown as an annotation on the job (readable through the API); a
  manual release run can skip the test suite (`gh workflow run release.yml -f quick=true`; a tag always runs it).
- **Approvals for the front ends:** `sandbox-ai approvals list --json` carries each question's `timeout`, its
  `seconds_left` (computed on its own host, so another machine's clock does not matter), the widest scope an
  allow keeps (`max_scope`) and a browser question's URL.
- **One SSH connection per host:** commands to another host share one connection for a minute (a master started
  on its own, its socket in a private folder of `XDG_RUNTIME_DIR`); the app and the web poll other hosts without
  a handshake each time. `SANDBOX_AI_SSH_MULTIPLEX=0` switches it off.
- **The macOS app starts again:** its launcher read a variable before setting it (and stopped under `set -u`);
  both launchers are now tested under `sh -eu`. The macOS disk images pass their install check on arm64 and
  x86_64.
- **Web: approvals of every host on one page.** The badge, the tab title and a countdown per question (amber, red,
  expired) cover all hosts at once; answers go to the question's own host; a host that cannot be reached says so
  instead of showing 0. A browser question shows its link, opened where you are ("Opened it — allow"). Deny holds
  for the run; "Block always" asks first.
- **Web: one rule for confirmations.** Stop, delete, removing a limit, blocking always and lowering a host's
  defaults (mode lax/low, telemetry on, canaries off) are confirmed in the page, naming host and start, and the
  server refuses them without. A stopped kept start shows what changed in its HOME before it resumes.
- **Web: the rest.** Open terminals survive page changes; start options are split like a shell line (`-m sonnet`);
  MCP rows offer only what applies to them; the starts page refreshes itself; `net show` is a table with Revoke
  per row; the page is kept in the address (reload, Back); screen readers hear toasts and the approvals count
  only.
- **Workspaces:** `/proc`, `/sys` and `/dev` are refused as workspaces (at a start and live, read-only too), and a
  live add checks the file system of every mount it would bring in; no live add without `mount_setattr`
  (Linux 5.12); a removal that fails half-way puts the workspace back where it was taken away; `workspace remove`
  tells a name from a directory and refuses an ambiguous one.
- **Limits:** on Podman `sandbox-ai limits` changes the container's own limits (before: the pod's, which did not
  bind); `sandbox-ai limits RUN --show [--json]` shows the current ones; the memory watch follows the smallest
  limit above the sandbox and puts back a `memory.high` that systemd reset.
- **Canary tokens below a wildcard:** a looked-up name carrying a canary token is refused and reported, never
  asked about, never looked up on the host, even below an allowed `*.DOMAIN` (before, such a name was answered
  on the host).
- **Wildcards checked against the Public Suffix List:** a pinned copy ships with sandbox-ai (ICANN and private
  sections, SHA-256 in its header); `*.X` is refused when X is a public suffix or one lies below it, and for
  known tunnel and capture services (`webhook.site`, `interact.sh`, `devtunnels.ms` ...). Lookups below a
  wildcard have a budget of their own and never use up the run's questions; the cap of names per wildcard holds
  under concurrent answers; concurrent `net allow '*.X'` lose nothing.
- **`net show --keep` keeps what you gave:** names and addresses from `net allow` and "always" approvals,
  wildcards, networks, DNS, ports, devices, workspaces; what a question opened only once or for the run needs
  `--keep-all`. Every option is shown before writing; refused while the policy caps answers below "always".
- **`sandbox-ai approvals allow ID --no-open`** answers a browser question without opening a browser on that host
  (the page was opened where you are).
- **The desktop app:** questions of every host in one Approvals table (read every 5 s in the background, a
  countdown each, notifications, "Open here" for a browser question of another host); running starts of other
  hosts get their network, workspaces, devices and limits changed there; the HOME review before resuming a kept
  start; Cancel as the default of every delete; a host filter on the Sandboxes page; the Hosts page asks before
  Stop and Remove, follows the state and keeps its selection. The app's version now follows sandbox-ai's.
- **Web in English and German**, with the app's terms; the language from the header's choice or the browser.
- **The app manages the fleet:** the Hosts page lists every host (answered, version, running starts, open
  questions) and leads to their starts and questions; the Sandboxes page reads the hosts every 10 s while shown
  (each host on its own), marks starts that ask, and greys the rows of a host that stopped answering ("last seen").
  Rename, an ended view with History, Clean up (`gc` after a preview), Untaint, remembered answers per host
  (forget them there), Edit host, a host's defaults (a step down in security asks first) and a new LLM servers
  page. Answers are per question (a slow host holds up no other); "Deny for this run" and "Deny once"; Block
  always asks first; Alt+A, Alt+D, Ctrl+Shift+B on Approvals; a notification selects its question.
- **SSH connections shared safely:** one master per host across processes (a lock file beside the socket), started
  within the command's own timeout, a failed start not retried for a minute, a dead master left for a direct retry;
  also on macOS (a private cache folder) and without `XDG_RUNTIME_DIR`; `hosts remove` ends the master.
- **Browser questions** never expire in the front ends; their URL is given whole and only when the host would open
  it, with the real destination host beside it.
- **A security mode capped at "once"** refuses a DNS allow instead of widening it to the run.
- **The memory watch stays inside the sandbox's own cgroup** (never the desktop session's above it).
- **Workspaces:** a timed-out add whose undo is not sure stays listed (pending, with a note); a kept workspace gets
  the place a restart will give it; `net allow --keep` holds to the policy as `net show --keep` does.
- **A task taken for running:** a foreground start counted as running while any process with an argument ending
  in `agent_sandbox.py` (such as `test_agent_sandbox.py`) had its PID; the launcher's file is now matched by name.
- **The user's socket folders stay out of every sandbox:** a workspace, a mount (read-only too) or `--state-dir`
  that is, holds or lies in `XDG_RUNTIME_DIR`, `/run/user/UID` or sandbox-ai's folders for shared SSH connections
  is refused (a socket can be reached through a read-only mount).
- **Kernel file systems below a workspace:** a start refuses a workspace or mount that has a procfs, sysfs, cgroup
  or another of the kernel's own file systems mounted below it (a chroot, a build root): the sandbox's binds are
  recursive. A live `workspace add` already refused them.
- **Web: one confirmation table.** `NEEDS_CONFIRM` lists every action that ends, removes or widens something
  (removing a host, VPN, LLM server or a kit's skill or plugin, `net allow`, allow "always", untaint, gc, forget,
  limits above the current ones, any step down in a host's defaults by rank); the page asks from the same list
  (`GET /api/policy`), the server refuses without, and a test fails for a new route that is in neither list.
- **Web: the fleet.** `GET /api/starts` reads every host (one request in flight per host, the last answer reused
  meanwhile) with a host column, an "asking" badge and greyed rows of a host that stopped answering; the host is
  in the address (`#starts@ct101`). Rename, history, clean up (`gc` after a preview), untaint, approvals history,
  remembered answers (forget them), editing a host and a Secrets page (values only ever sent on stdin).
- **Web: answers that hold.** One toast per question set, an answered question never comes back with live
  buttons, countdowns minus each host's answer age, browser questions only "Open here and allow", "Deny for this
  run" / "Deny once" as sent; a session about to end says so two minutes before ("Stay logged in"), and after it
  ended the login names the questions that were open; the first run shows a checklist; focusable approval rows
  with `a`/`d` and announced time left.
- **A command to another host never runs twice:** when the shared connection seems dead it is asked to stop
  taking sessions (`-O stop`, what runs through it goes on), and a command runs again on a connection of its own
  only when it never reached the host.
- **The destination of a browser question** is the host a browser opens (percent-encoding and odd full stops
  decoded, leading slashes and backslashes skipped); `--state-dir` gets the kernel file system check too.
- **Paths inside a kernel file system** mounted elsewhere (a chroot's `proc`) are refused as workspaces, mounts
  and `--state-dir`; `--log-dir` and `--gui-vnc` get the socket, private-location and kernel checks too; a socket
  file is never a `--mount` source.
- **Hosts:** an SSH identity must be a key file in your HOME (and only private keys are ever made private); a
  host's command cannot start with `-`; `hosts.json` changes hold a lock (`hosts_file_lock`), so the CLI and the
  web never lose each other's edits.
- **Web, round 3:** a confirmation is bound to what it showed (a secret's name, clean-up's days and list: the
  server refuses with 409 if `gc` would now remove more than the preview); a refusal that needs a confirmation
  brings up the confirm; attaching or restarting an MCP server, adding to a kit, editing a host's connection,
  lowering `keep_days` and other defaults' changes are confirmed (only known defaults keys); a damaged
  `hosts.json` is reported instead of dropping the connection; typing in a terminal keeps the session alive;
  states in German; buttons named with start and host; rows and cards survive a rename; the Hosts page counts
  starts and open questions; a session that ended says so in the title.
- **`sandbox-ai hosts install NAME`** puts sandbox-ai onto a host that has none yet (or reinstalls it): this
  machine's own copy (`--from-here`, the default: the host needs no release server) or the signed release the
  host downloads itself (`--download [--version X.Y.Z]`); for the SSH user (`--user`, the default unless that is
  root) or for every user (`--system [--prefix DIR]`): as root over SSH, or with sudo (`sudo -n`; when sudo wants
  a password, the terminal asks). `--no-sudo` never uses it. `hosts update` skips sudo when the SSH user is root.
- **You decide what a sandbox gets:** a workspace, mount or `--state-dir` in a private location of yours
  (`~/.config/axross`, `~/.ssh`, a folder on your PATH …) is given, with a warning that names what the agent sees
  there and what it could change (before: refused). Only sandbox-ai's own folders (its configuration and trust
  store, state, approvals, logins) stay refused: a sandbox given them could change sandbox-ai itself.
- **Web: install and update hosts** (for the SSH user or every user, as root, with sudo or without, this machine's
  copy or the signed release; one install per host at a time, its state readable while it runs); **a readable
  doctor** (grouped by area, problems first, fix commands with Copy, the fine checks folded); **starts grouped by
  host** (local or remote on every row, answering or last seen) with each start's MCP servers and helpers under
  it, folding kept across refreshes.
- **Web: what the command line can do.** New pages for MCP servers (list, start with backend/VPN/for a start, stop,
  catalog, add with every option), logins (Git, publish, identities; agent login and logout, plugins), images and
  tools (build, the demo device), projects (review a `.sandbox-ai.json`, trust exactly the shown digest, forget),
  presets (show, check, preset folders) and activity (filtered, followed); the network card has `--allow`, the
  presets, `--nameserver`, `--git-token-file` and keeping for later starts; resume with restart, workspace, mount
  or MCP server, stop with a wait, ended starts; canaries per run; kit hooks; LLM and VPN with every option (Tor
  included); log folders and the privacy check; the doctor's backend, a host's `version --verbose`, a version for
  host updates; a model choice beside the agent (the provider's cloud or a model server of that host).
- **`sandbox-ai wizard trust PATH --show [--json]`, `--digest SHA256`, `--list [--json]`**: review a project file,
  trust exactly the digest you saw, list what is trusted.
- **Presets:** every preset is checked with every agent it allows by a test that dry-runs it through the launcher
  (so a broken preset fails CI); new: `tor` (everything through a Tor VPN profile), `local-api` (any
  OpenAI-compatible server, the raw API), `ollama`, `lm-studio`, `llama-cpp` and `vllm` (a local model, no cloud);
  a model value takes `NAME:MODEL`; `presets check` names a VPN profile or LLM server that is missing, that the
  agent cannot use or that has no model; `presets show` prints each value's hint.
- **MCP:** a refused `mcp add --unsigned` no longer says "added".
- **The app's Files page has two panes:** a sandbox's folder and this machine; copy and move both ways, delete,
  rename, new folder, permissions, owner and group, and "take ownership" of what the agent wrote with a
  subordinate UID (through `podman unshare`, never following a link); F5/F6/F7/F8/F2/Tab; everything below a
  sandbox treated as the agent's (no links followed, nothing half-written left behind).
- **The app's Sandboxes page is a tree:** the hosts (this machine and each remote host, with counts and whether
  it answers), their starts, and under each start what belongs to it (MCP servers, helpers, its pod, companions,
  teams); folds and selection kept across refreshes and restarts; Fold all / Unfold all act on it.
- **The app's wizard has a Model step:** the provider's cloud or a model server of your own (LM Studio, Ollama,
  llama.cpp, vLLM or any OpenAI-compatible API): add one (URL with the kind's port, optional key and VPN),
  check it, pick its model, "only this server"; the Start page and the Board get the same choice beside the
  agent; OpenCode, Codex and Claude (with an Anthropic-API server) start with it.
- **The app:** a Settings menu (Ctrl+,); the icon strip shows every icon (with the approvals count) and its toggle
  sits on top; Fold/Unfold all work; one row per kept start (no stopped twin); the last 10 project folders in the
  wizard; host install and update with sudo, root or without; a readable doctor; the confirmation table shared
  with the web.
- **The app does what the command line does, on this machine and on your hosts:** start an agent on a host (Start
  page, Board, presets; the options that host's sandbox-ai knows), resume with workspaces, mounts, MCP servers or
  a restart, stop with a wait; the network dialog's nameservers and "keep for later starts"; the MCP page per host
  with every option; the privacy check with its options; `version --verbose` and updating to a version; the
  demo device; VPN, kits (hooks, plugins), secrets, Git and publish logins, identities, preset folders, trusted
  projects and images (extensions, recipes, history, build with options) per host; activity and statistics per
  host; agent login and logout on a host; a Teams page; LLM and VPN with every option (Tor included); canaries
  per run (tokens and resume asked first).
- **MCP servers into a running sandbox:** `sandbox-ai mcp attach NAME START --live` (and `--helper AGENT`) starts
  the server if needed, opens its relay in the running sandbox (approvals, MCP rules, the taint and the call log as
  at a start), records it and keeps it for the next start; Claude Code finds it in `/mcp`, Codex and OpenCode
  read their servers at start (`resume START --restart` keeps the conversation). `mcp detach NAME START --live`
  takes it away again. The supervisor now reaches every server's socket without following links.
- **Mounts with a name, and single files:** `sandbox-ai workspace add [RUN] DIR|FILE [--ro] [--name NAME]` puts a
  folder or a file at `/workspaces/NAME`; a named folder keeps its name for the session's next start.
