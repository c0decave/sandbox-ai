# sandbox-ai 0.1.78

0.1.78 carries everything listed for 0.1.77 (that release never reached GitHub or PyPI: its macOS install check
failed), and on top:

- **`sandbox-ai ps` groups and colours:** each start is followed by its MCP servers and helpers (`├─`, `└─`); a
  server several starts use is shown below the one it was started for (new in `mcp.json`: `started_for`) and names
  the others; servers no start uses come last. `--flat` gives the plain table of before. On a terminal the kinds
  and states are coloured (`--no-color`, `--color=always|auto|never`, `NO_COLOR`; never with `--json` or a pipe).
  `list --json` adds `listed_under` and an MCP server's `started_for`. `sandbox-ai ps --help` now says `ps`.
- **Workspaces, devices and limits from the app and the web:** the app's "While it runs" box adds a workspace
  (read-only, or writable after a confirmation) and removes one (a busy one is detached only after asking), and
  lists the workspaces added during the run. The web interface has a Resources card for every running start, on
  any host: its workspaces, devices and resource limits, with a writable workspace, a device or a forced removal
  confirmed first (the server refuses them without).
- **Pushes from a workspace added during the run:** the push check takes its commits, with the run's rules and
  its project's own privacy rules (`push-added.json` beside the run's `push.json`, written on the host); the
  privacy check after the run looks at the writable ones too. Before, such pushes to a public remote were refused.
- **Each start workspace with its own project's rules** in the push check, read-only ones included (a mix of
  read-only and writable workspaces could pair a workspace with another project's rules).
- **Host wildcards in the app:** the Allow dialog explains `*.DOMAIN`.
- **Releases:** a failed check of a package is shown as an annotation on the job (readable through the API); a
  manual release run can skip the test suite (`gh workflow run release.yml -f quick=true`; a tag always runs it).
- **Approvals for the front ends:** `sandbox-ai approvals list --json` carries each question's `timeout`, its
  `seconds_left` (computed on its own host, so another machine's clock does not matter), the widest scope an
  allow keeps (`max_scope`) and a browser question's URL.
- **One SSH connection per host:** commands to another host share one connection for a minute (a master started
  on its own, its socket in a private folder of `XDG_RUNTIME_DIR`); the app and the web poll other hosts without
  a handshake each time. `SANDBOX_AI_SSH_MULTIPLEX=0` switches it off.
- **The macOS app starts again:** its launcher read a variable before setting it (and stopped under `set -u`);
  both launchers are now tested under `sh -eu`. The macOS disk images pass their install check on arm64 and
  x86_64.
- **Web: approvals of every host on one page.** The badge, the tab title and a countdown per question (amber, red,
  expired) cover all hosts at once; answers go to the question's own host; a host that cannot be reached says so
  instead of showing 0. A browser question shows its link, opened where you are ("Opened it — allow"). Deny holds
  for the run; "Block always" asks first.
- **Web: one rule for confirmations.** Stop, delete, removing a limit, blocking always and lowering a host's
  defaults (mode lax/low, telemetry on, canaries off) are confirmed in the page, naming host and start, and the
  server refuses them without. A stopped kept start shows what changed in its HOME before it resumes.
- **Web: the rest.** Open terminals survive page changes; start options are split like a shell line (`-m sonnet`);
  MCP rows offer only what applies to them; the starts page refreshes itself; `net show` is a table with Revoke
  per row; the page is kept in the address (reload, Back); screen readers hear toasts and the approvals count
  only.
- **Workspaces:** `/proc`, `/sys` and `/dev` are refused as workspaces (at a start and live, read-only too), and a
  live add checks the file system of every mount it would bring in; no live add without `mount_setattr`
  (Linux 5.12); a removal that fails half-way puts the workspace back where it was taken away; `workspace remove`
  tells a name from a directory and refuses an ambiguous one.
- **Limits:** on Podman `sandbox-ai limits` changes the container's own limits (before: the pod's, which did not
  bind); `sandbox-ai limits RUN --show [--json]` shows the current ones; the memory watch follows the smallest
  limit above the sandbox and puts back a `memory.high` that systemd reset.
- **Canary tokens below a wildcard:** a looked-up name carrying a canary token is refused and reported, never
  asked about, never looked up on the host, even below an allowed `*.DOMAIN` (before, such a name was answered
  on the host).
- **Wildcards checked against the Public Suffix List:** a pinned copy ships with sandbox-ai (ICANN and private
  sections, SHA-256 in its header); `*.X` is refused when X is a public suffix or one lies below it, and for
  known tunnel and capture services (`webhook.site`, `interact.sh`, `devtunnels.ms` ...). Lookups below a
  wildcard have a budget of their own and never use up the run's questions; the cap of names per wildcard holds
  under concurrent answers; concurrent `net allow '*.X'` lose nothing.
- **`net show --keep` keeps what you gave:** names and addresses from `net allow` and "always" approvals,
  wildcards, networks, DNS, ports, devices, workspaces; what a question opened only once or for the run needs
  `--keep-all`. Every option is shown before writing; refused while the policy caps answers below "always".
- **`sandbox-ai approvals allow ID --no-open`** answers a browser question without opening a browser on that host
  (the page was opened where you are).
- **The desktop app:** questions of every host in one Approvals table (read every 5 s in the background, a
  countdown each, notifications, "Open here" for a browser question of another host); running starts of other
  hosts get their network, workspaces, devices and limits changed there; the HOME review before resuming a kept
  start; Cancel as the default of every delete; a host filter on the Sandboxes page; the Hosts page asks before
  Stop and Remove, follows the state and keeps its selection. The app's version now follows sandbox-ai's.
- **Web in English and German**, with the app's terms; the language from the header's choice or the browser.
- **The app manages the fleet:** the Hosts page lists every host (answered, version, running starts, open
  questions) and leads to their starts and questions; the Sandboxes page reads the hosts every 10 s while shown
  (each host on its own), marks starts that ask, and greys the rows of a host that stopped answering ("last seen").
  Rename, an ended view with History, Clean up (`gc` after a preview), Untaint, remembered answers per host
  (forget them there), Edit host, a host's defaults (a step down in security asks first) and a new LLM servers
  page. Answers are per question (a slow host holds up no other); "Deny for this run" and "Deny once"; Block
  always asks first; Alt+A, Alt+D, Ctrl+Shift+B on Approvals; a notification selects its question.
- **SSH connections shared safely:** one master per host across processes (a lock file beside the socket), started
  within the command's own timeout, a failed start not retried for a minute, a dead master left for a direct retry;
  also on macOS (a private cache folder) and without `XDG_RUNTIME_DIR`; `hosts remove` ends the master.
- **Browser questions** never expire in the front ends; their URL is given whole and only when the host would open
  it, with the real destination host beside it.
- **A security mode capped at "once"** refuses a DNS allow instead of widening it to the run.
- **The memory watch stays inside the sandbox's own cgroup** (never the desktop session's above it).
- **Workspaces:** a timed-out add whose undo is not sure stays listed (pending, with a note); a kept workspace gets
  the place a restart will give it; `net allow --keep` holds to the policy as `net show --keep` does.
- **A task taken for running:** a foreground start counted as running while any process with an argument ending
  in `agent_sandbox.py` (such as `test_agent_sandbox.py`) had its PID; the launcher's file is now matched by name.
- **The user's socket folders stay out of every sandbox:** a workspace, a mount (read-only too) or `--state-dir`
  that is, holds or lies in `XDG_RUNTIME_DIR`, `/run/user/UID` or sandbox-ai's folders for shared SSH connections
  is refused (a socket can be reached through a read-only mount).
- **Kernel file systems below a workspace:** a start refuses a workspace or mount that has a procfs, sysfs, cgroup
  or another of the kernel's own file systems mounted below it (a chroot, a build root): the sandbox's binds are
  recursive. A live `workspace add` already refused them.
- **Web: one confirmation table.** `NEEDS_CONFIRM` lists every action that ends, removes or widens something
  (removing a host, VPN, LLM server or a kit's skill or plugin, `net allow`, allow "always", untaint, gc, forget,
  limits above the current ones, any step down in a host's defaults by rank); the page asks from the same list
  (`GET /api/policy`), the server refuses without, and a test fails for a new route that is in neither list.
- **Web: the fleet.** `GET /api/starts` reads every host (one request in flight per host, the last answer reused
  meanwhile) with a host column, an "asking" badge and greyed rows of a host that stopped answering; the host is
  in the address (`#starts@ct101`). Rename, history, clean up (`gc` after a preview), untaint, approvals history,
  remembered answers (forget them), editing a host and a Secrets page (values only ever sent on stdin).
- **Web: answers that hold.** One toast per question set, an answered question never comes back with live
  buttons, countdowns minus each host's answer age, browser questions only "Open here and allow", "Deny for this
  run" / "Deny once" as sent; a session about to end says so two minutes before ("Stay logged in"), and after it
  ended the login names the questions that were open; the first run shows a checklist; focusable approval rows
  with `a`/`d` and announced time left.
- **A command to another host never runs twice:** when the shared connection seems dead it is asked to stop
  taking sessions (`-O stop`, what runs through it goes on), and a command runs again on a connection of its own
  only when it never reached the host.
- **The destination of a browser question** is the host a browser opens (percent-encoding and odd full stops
  decoded, leading slashes and backslashes skipped); `--state-dir` gets the kernel file system check too.
- **Paths inside a kernel file system** mounted elsewhere (a chroot's `proc`) are refused as workspaces, mounts
  and `--state-dir`; `--log-dir` and `--gui-vnc` get the socket, private-location and kernel checks too; a socket
  file is never a `--mount` source.
- **Hosts:** an SSH identity must be a key file in your HOME (and only private keys are ever made private); a
  host's command cannot start with `-`; `hosts.json` changes hold a lock (`hosts_file_lock`), so the CLI and the
  web never lose each other's edits.
- **Web, round 3:** a confirmation is bound to what it showed (a secret's name, clean-up's days and list: the
  server refuses with 409 if `gc` would now remove more than the preview); a refusal that needs a confirmation

  `hosts.json` is reported instead of dropping the connection; typing in a terminal keeps the session alive;

### Security fixes (review round 5)

- **A sandbox's Claude login goes back to the host only if it is a refresh of the same account.** The live login
  sync wrote a changed `~/.claude/.credentials.json` of a sandbox back to its source (the host's login or the
  login store) whenever the source still held what the two had shared, without asking whose login it was: a
  `/login` with another account inside a sandbox replaced the host's login, and an agent could plant its own
  account's tokens there, so that Claude on the host then talked to that account. Now the launcher asks
  Anthropic, on the host and the way Claude Code does (`GET https://api.anthropic.com/api/oauth/profile` with
  the access token, TLS verified, no redirect followed, 5 s), which account and organization the sandbox's new
  token belongs to, and compares it with the source's (its own `~/.claude.json` `oauthAccount`, else the same
  question with the source's still valid token, once per run). Only the same account is written back, during the
  run, at its end and at the next start of a killed run; another account, or one that cannot be checked, stays in
  the sandbox and the source keeps its own login (said after the run, never with a token). If Anthropic cannot be
  asked, nothing is written back and it is asked again at the next change, at most once a minute, and once more
  at the end. Not covered: an agent that refreshes the login itself could still pair the new access token of the
  right account with another account's refresh token, which Anthropic cannot check without using it up.
- **No credential goes with a `Host` header naming another server.** The proxy added `--api-key`, `--llm` (key
  and header secrets), publish and Git login credentials by the TLS name it checked alone; a request to
  `mine.hf.space` with `Host: other.hf.space` reached the other tenant with your key (domain fronting). Such a
  request is now refused with a `sandbox-ai: ...` 403 and logged (case, a trailing dot and the default port
  don't count; plain http to an `--llm` server needs its name or pinned address).
- **A request question names where the request goes:** the server the proxy verified (over plain http, the
  address), not the `Host` header the agent wrote; a different `Host` is shown as an unverified claim, and the
  connection log records the real URL with the claim as `host_header`.
- **A writable `--mount`, `--state-dir` or MCP server folder that holds sandbox-ai's launcher** (e.g. `~/c0de`
  holding a checkout, a venv holding the package) is refused, as a workspace already was: the agent could
  rewrite the launcher and the next start would run it on the host. Read-only mounts stay allowed.
- **Test connection sends no key over plain http to a public address:** `wizard models --url` (the app's and the
  web's Test connection) now checks the URL as `llm add` does before a key leaves; `--insecure-http` (in the web:
  the ticked box, asked first) allows it.
- **Web:** replacing a publish login, an identity's login or an MCP server of the same name is asked first
  (`login-replace`, `mcp-replace`); a start's terminal is read for the "not trusted" offer only until the sandbox
  runs, so an agent's output can't raise it; a catalog's text can't forge another row of the MCP table (`mcp
  catalog` prints one line per entry, its texts printable); a request must send its headers within 10 s and its
  body within 30 s, and one address other than this machine's holds at most 16 connections. `mcp add` says when
  an entry gets the full outside network.
- **Starts sandbox-ai builds itself keep their `/work`:** team members, `resume`/`restart` (the folder that was
  `/work` at the first start is recorded), web starts also without a workspace field, and starts on another host
  whose sandbox-ai is 0.1.78 or later pass `--workspaces-as-given`, so a project file in the directory they run
  from (the web service's, the SSH login's HOME, one the agent wrote later) never takes them over.
- **Proxy, smaller holes closed:** an `--llm` key below a path prefix and an allow rule for some paths no longer
  go by a path that servers read differently (`/tenantB/x%2F..%2F..%2FtenantA/...`: a dot segment after
  decoding); SSH to a public Git host is refused also after a junk line before the client's banner (any early
  line counts, and the server's banner too); `git push -o` options (GitLab's merge request title and
  description) go through the privacy check with the commits.
- **`hosts install --system --prefix`** checks every folder from `/` down to `PREFIX/lib/sandbox-ai`: each must
  belong to root or the SSH user and not be writable by a group or others (a sticky folder above, as `/tmp`, is
  fine); the remote install runs `git` only in a checkout's own repository, never one of a folder above.

### Fixes (review round 5)

- **Settings files lose no change any more:** `llm.json`, `git-logins.json`, `publish-logins.json` and
  `identities.json` are read and written back under a lock (12 parallel `llm add` kept 5 servers before; an
  `llm remove` racing `llm models` brought the server back).
- **`hosts list --refresh` no longer fails now and then** with "has no attribute 'printable'": helper modules are
  used only once they have finished loading (also in the web interface's request threads).
- **`team start NAME --agents A,B -w DIR -- OPTIONS`** works as documented (and as the web sends it); before,
  everything after NAME was taken as options. `team list` shows a damaged team instead of failing, and
  `team delete NAME --yes` removes it.
- **`--workspace .` (or `$PWD/`, `../proj`) where the directory holds a project file** no longer fails with
  "Workspaces must not overlap: X and X"; a `--workspace` inside or around it is the folder you chose.
- A `session.json` of another shape shows as damaged instead of crashing `list`, `ps` and `session list`; a
  project file for another agent says `start it with sandbox-ai AGENT, or ... --no-config` (and one without an
  agent says so).

### Desktop app (review round 5)

- **Trusting a project file shows what is trusted:** the Board's Apply, the wizard's Finish and the Start page's
  Review and Write and trust name every key of the file (the security mode, canaries, a kept HOME, debug logs,
  name, rules, MCP servers, options), mark what weakens the sandbox with ⚠, and show the changes against the
  version you trusted last - never against the file in the folder, which the agent can write. A key the launcher
  does not know is no longer carried along, and the Board names the file's keys it has no part for.
- **A Board start keeps the project's security settings:** its mode, canaries, kept HOME, debug logs, name and
  ruleset reach the start and the dry run (a paranoid project started as medium before); a ruleset on another
  host is refused instead of dropped.
- **Hosts and Activity no longer make the window wider than the screen** (1700-1900 px before): their rows wrap,
  long choices are shortened (whole in the list and the tooltip), a page wider than the window scrolls sideways,
  and the window can be made small again after every page was shown. The German navigation is wide enough for
  its titles; the (?) of a table no longer covers its last column's title.
- **Every host chooser follows the Hosts page:** a host added, renamed or removed shows up (or goes) at once on
  Activity, Statistics, Kits, Images, Credentials and every other page; a page whose host left goes back to this
  machine.
- **The Start page in German:** its options carry German labels with the option name below, sandbox-ai's help as
  the tooltip, and the ones that weaken the sandbox in the warning colour when set; every choice, table and filter

- **A start always names its workspace:** with the field empty the project folder chosen is used (said), else

- **Clean up… with "All hosts"** cleans the selected start's host (or asks to choose one), and its question names
  the host; a login whose server address sandbox-ai would refuse is said in the dialog before any token is stored
  (one stored for a refused login is removed again).
- Smaller: USB devices by identity (`usb:VENDOR:PRODUCT`) can be added and removed while a sandbox runs; an MCP

  options that only newer sandbox-ai versions know are said plainly ("update the host") instead of failing there;

  rich text; German wording: one word for each thing (Rechner, Arbeitsordner, Tafel, Vorlage, Protokolle).
- **The app on another host, as on this machine:** a project file there is reviewed and trusted from Settings

### Web interface (review round 5)

- **More… resumes a paused start:** the restart it needs is offered and ticked for paused starts too (before,
  everything added to a paused start was refused); on a stopped start the kept HOME is reviewed first, as Resume
  does; a run without a kept start gets only the longer stop, and "Restart the agent now" is not offered for it.
  The More and History cards follow a rename, and More is switched off when the start's state changes.
- **Test connection while editing an LLM server with its own CA** tests with that CA (`wizard models --ca-of
  NAME`, read on that host), instead of failing on the certificate.
- **A start names its workspace:** the Start form (and a team start) needs the folder the agent works on, in the
  field or as `--workspace`/`-w` in the options; without one nothing starts and the form says why - the folder the
  web service runs in (or the SSH login's HOME on another host) never becomes `/work`.
- **A login is checked before its token is stored:** a Git or publish login's server is checked as sandbox-ai
  checks it (https, no path; plain http only to this machine) before the token becomes a secret, and a publish
  login that replaces one is asked first; a refusal is said below the form, which keeps what was typed. When the
  host refuses the login after all, a secret stored for it under a new name is removed again.
- **German as the app has it:** one word for each thing (Arbeitsordner, Ordner, Protokolle, Anmeldungen,
  Datenschutz, Taint aufheben, sperren, erzwungen), and every text the app has too reads the same in both.
- **Logs and Activity read a start of that host, never the web service's own folder:** they show the first
  start's project (Logs) or the first running start (Activity, a session by `--session`, a plain run by its
  name), or ask for one; Activity can also read a project, a log directory or a sandbox HOME. The form stays when
  there is nothing to show: "no logs yet" is said below it instead of replacing the page.
- **Hosts with an older sandbox-ai:** what only 0.1.78 knows (allowing a browser question without opening a
  browser there, the Projects list and review, Test connection, a workspace with a name, the limits shown, "keep
  everything", MCP servers while a start runs) is no longer sent to a host whose last status names an older
  version: the page says "update it on the page Hosts" instead, and the rest of the page works. A browser
  question of such a host opens nothing here.
- Smaller: the project wizard runs in a terminal of the Projects page (new, or edit a file); the Logins page shows
  which login each agent's sandboxes get (`login --status`); a build takes `--pin`, `--uv` and `--node`; an "All
  ports" network row has its Revoke; a start's new name is checked against the launcher's 40 characters;
  choosing a model server drops `-mm=X`/`-lm=X` from the options too; the version cell follows an update from
  this machine's copy.
- **An LLM server's key can be typed where the server is added**, on every host: it is stored as the secret named
  first (a secret of that name is asked about), and removed again when the server is then refused.
- **A plugin marketplace you can use:** `sandbox-ai plugins marketplaces [--json]` lists every marketplace on the
  machine with its plugins and each plugin's state: sandbox-ai's own, the kits' (yours, the default kit's, the
  built-in ones), the plugin store's, and the ones Claude (`~/.claude`), Codex (`~/.codex/config.toml`) and OpenCode
  (its npm plugins in `opencode.json`; it has no marketplaces) already know. It only reads: a missing or damaged
  agent file is a note. New kit commands: `enable-plugin`, `disable-plugin` (declared and installed but off, also
  over the default kit's), `remove-marketplace [--with-plugins]` and `import-marketplace KIT NAME [--from
  claude|codex] [--with-plugins]` (a marketplace an agent knows, with the source it has there); the plugin and
  marketplace commands also change the default kit (`default`). `sandbox-ai plugins claude --marketplaces-only`
  fetches the kits' marketplaces so their plugin lists show, installing nothing. Shell completion knows the new
  commands, kits, marketplaces and plugins.
- **Web: the Kits page is a marketplace browser:** pick a marketplace, see its plugins with their state, add one
  to a kit (or the default kit), enable, disable or remove it there, add or remove a marketplace, import one
  Claude or Codex knows on that host, fetch the plugin lists in a terminal. A host with an older sandbox-ai is
  asked to be updated.
- **App: the Kits & plugins page is a marketplace browser too** (its tab Marketplaces), on this machine or a host:
  choose a kit (the default kit or one of yours; built-in ones are shown read-only, with the reason) and a
  marketplace, filter its plugins and see their state (in which kits, on or off, in the plugin store, in the
  agent's own configuration); add to the kit, enable, disable, remove; add a marketplace, import Claude's (with
  the plugins Claude enables) or Codex's (for Claude), remove one with or without its plugins; OpenCode's npm
  plugins alike; Fetch the plugin lists in a terminal (installs nothing). Every change is asked first naming the
  host and the kit; the agents' own files are only read. A host with an older sandbox-ai is told to update
  (Hosts › Update) and its kits work as before. The Kits tab shows disabled plugins and removes the default kit's.
- **Security (review 5, M4): copying a kit can no longer pull host files into a sandbox.** A kit entry linked from
  a checkout an agent can write was copied by path: swapping one of its folders for a symlink (to `~/.ssh`, say)
  while a start copied it sent host files into the new sandbox. The copy now walks from directory handle to
  directory handle, opens nothing through a symlink and checks each opened folder is the one it listed; below a
  kit entry symlinks are skipped with a note (they were followed while they stayed inside the entry).
- **Security (review 6, M-A): a kit link re-pointed by an agent no longer copies host files.** A kit entry linked to
  a skill in a checkout (`~/kit/claude/skills/foo -> ~/src/proj/skills/foo`) was resolved in one go: an agent
  working on `~/src/proj` could replace `skills/foo` with a link to `~/.ssh`, and the next start copied the keys.
  Kit entries, memory templates, `marketplaces.json` (at the start and in `sandbox-ai plugins claude`) and
  `--kit-dir` are now followed one link at a time; the start stops at a link that lies in a folder a sandbox can or
  could write (this run's, an earlier run's, a running sandbox's or a kept session's workspace), naming the link and
  what to do. A kit entry that comes from such a folder is still copied, with a note. The same link-by-link test
  now covers `--mount`, `--state-dir`, `--log-dir` and workspaces given through your own links.
- **Security (review 6, L-1): `sandbox-ai workspace add` refuses the launcher the start runs**, not only its own:
  a sandbox started from a checkout could get the checkout's parent added through the installed CLI, the web or
  the app. The start records its launcher folders and package for later adds.
- **Security (review 6, L-2): a pip install's virtualenv counts as sandbox-ai's launcher** (its `bin/` holds the
  `sandbox-ai` entry script), as does `~/.local/bin` for a `pip --user` install: no writable workspace or mount may
  be, hold or lie in it.
- **Security (review 6, L-3): a push with more than 100 push options is refused.** The privacy check read only the
  first 100 options (`git push -o`) and the proxy forwarded the rest unchecked, so a secret or canary placed after
  100 padding options reached the forge.
- **Security (review 6, L-4): `llm check` and `llm models` no longer send a key over plain http to a public
  address.** A server registered as `http://gpu-box.lan:11434` whose name later resolved to a public address got the
  key anyway (from the web, the app and the wizard too). Every request with a key or header secret over plain http
  now resolves and checks the name first and connects to the address checked; only a server added with
  `--insecure-http` is exempt, as with `llm add`.
- **Security (review 6, L-8): the trusted list (`trusted.json`) is changed under its lock**, as the other settings
  files are: a `wizard forget` beside a `wizard trust` (the app and the web at the same time) can no longer re-trust
  a file that was just forgotten.
