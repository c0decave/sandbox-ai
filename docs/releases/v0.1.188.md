# sandbox-ai 0.1.188

**Everything since 0.1.94 in one release.** The last release on GitHub was 0.1.94; this one gathers what 0.1.95,
0.1.96, 0.1.97, 0.1.98 and 0.1.99 brought: nine new agents (OpenCode 2 among them), a sandbox browser, session
bridges, scheduled runs, workspace checkpoints, budgets, a secret guard and a package guard in the connection proxy,
a system monitor, remote folders, self-updates for every kind of installation, and the fixes of many review, test and
audit rounds. This page is the short form; the complete notes are linked at the end. Read *Changes in behaviour*
first if you come from 0.1.94.

## Changes in behaviour since 0.1.94

- **Build the agents' images again after updating:** `sandbox-ai build all`. Their telemetry guards are part of the
  images; images built before still start.
- **Telemetry is always off, for every agent.** The level `on` of `--telemetry` is gone (`off`, the default, and
  `strict` remain). An old `on` anywhere counts as not given and the start says so once; `defaults set telemetry on`
  is refused. Nothing passed with `--env` can switch an agent's telemetry back on.
- **No experimental gate any more.** `SANDBOX_AI_EXPERIMENTAL` is gone: choosing a new agent or `--nested-containers`
  starts it, and the start says in one line that it is not live-tested yet.
- **Kept starts expire.** Without `keep_days` in your defaults, `sandbox-ai gc` and its daily pass remove stopped kept
  starts unused for 90 days with their HOME - only 14 days after this was first said to you. Keep them all with
  `sandbox-ai defaults set keep_days 0`.
- **Logs older than 30 days go** (`log_days`, default 30; `sandbox-ai defaults set log_days 0`: never), again only 14
  days after it was first said. `gc` also compresses the logs of ended runs and splits a project's log over 96 MiB.
- **Less is logged:** file reads are summed per folder in `files.jsonl` (`defaults set file_reads files` for each read
  as before, `off` for none); a repeated request body in the connection log is a reference (`"same_as"`), a binary
  answer is logged by size and digest (`connection_bodies all`: as before).
- **MCP servers with network reach the internet, not your network.** `full` now refuses private and LAN addresses,
  this host and the cloud metadata address; the new `allowlist` (the default of allowlist catalog entries) reaches only
  the entry's hosts; `lan` is the opt-in for your network. Such servers need `nft` on the host (`sandbox-ai doctor`).
- **An unanswered approval question is no longer a refusal.** After the wait the request fails with "not answered
  yet", the question stays open and a later answer counts for the next try; nothing is refused for 2 minutes any more.
  `--ask-timeout SECONDS` sets the wait (default still 60 s).
- **The Approvals page is one table with tabs** (Open, Allowed, Refused, Timed out, All), in the app and the web; the
  Blocked and History sections and the confirmation windows of Allow always / Block always are gone (a note offers
  *Undo*). The scope box is three buttons: *Allow once*, *Always allow* (this run), *Always, also for later sessions*.
- **"Allow once" opens the destination for the connection that asked**, not for 30 seconds to every connection of the
  sandbox.
- **`sandbox-ai list` (`ps`) shows what runs**, as `docker ps`: `--stopped` (`-s`) adds stopped kept starts, `--mcp`
  (`-m`) the MCP server sandboxes, `--all` (`-a`) everything. `--json` lists everything as before.
- **Help and colours:** `sandbox-ai --help` and every command with subcommands are laid out like Docker's help, and
  output on a terminal is coloured. `--no-color`, `--color auto|always|never`, `NO_COLOR` and `TERM=dumb` turn it off;
  pipes, files, logs and `--json` never get colour.
- **Allow options take lists:** `--allow`, `--allow-host`, `--allow-domain`, `--allow-tcp`, `--allow-host-port`,
  `--nameserver`, `--no-inspect` and `--vpn-bypass-tcp` split one value at commas and spaces. One word per option
  still: `--allow-host a.example b.example` does not make `b.example` a second item - quote the list.
- **Mounts: you decide.** A host path you choose (`--workspace`, `--mount`, `--copy`, `--state-dir`, an MCP server's
  folder, ...) that was refused before is now given with a warning naming the risk. Symlinks a sandbox could have
  planted and private paths named by a passed-on preset stay refused.
- **The PyPI package is `sandbox-ai-app`.** The package named `sandbox-ai` on PyPI is not this project: never install
  it. `pipx install sandbox-ai-app`, with the desktop app `pipx install 'sandbox-ai-app[gui]'`.
- **`codex login` in a sandbox uses the device-code login** (the browser callback to the sandbox's loopback could never
  end). `SANDBOX_AI_LOGIN_CALLBACK=1` keeps the browser login; a loopback callback can be relayed once when you
  allow it.
- **Kits are mounted for every kind of the agent's layout**, empty and read-only where a kit has none: an agent no
  longer writes its own subagents or commands into `~/.claude/agents`, `~/.claude/commands`, `~/.codex/prompts` and the
  like (the project's own folders stay writable). Not with `--no-default-kit` and no `--kit`.
- **Tighter sandbox isolation:** sandbox-ai's own system call filter makes `io_uring`, new namespaces (`unshare`,
  `bwrap`) and sockets of other families fail in an ordinary sandbox (`--nested-containers` keeps what it needs;
  `SANDBOX_AI_SYSCALL_FILTER=off` once, refused in `high` and `paranoid`). Every host folder is mounted `nosuid`.
- **MCP rules judge every request:** `resources/read`, `prompts/get`, `completion/complete` and other acting requests
  are judged under their method's name, not only `tools/call`. If your ruleset's default for `mcp` is `deny` or `ask`,
  allow the resources and prompts you use by name (`"tool": "resources/read"`).
- **`sandbox-ai attach` and `shell` filter what the sandbox writes** before your terminal: clipboard and title
  requests, hyperlinks, notifications and DCS/APC strings are dropped (`SANDBOX_AI_TERMINAL_FILTER=strict|off`).
- **New guards on by default:** packages younger than 14 days are asked about and known malicious ones refused (the
  package guard); a secret sent to a host it was not given for is reported (the secret guard); workspace checkpoints are
  taken at every start (`--no-checkpoint` takes none). See the security section.
- **Kit imports with hidden text are refused** (`kits add-skill`, `kits host-import`, `kits attach`, `plugins attach`)
  unless `--allow-findings`; the agent instruction files of a workspace are checked at every start.
- **Reserved names are not asked about:** lookups of names below `.example`, `.invalid`, `.test` and `.localhost` are
  refused at once; an allowed name that does not exist closes its question ("denied for the run: NAME does not exist").
- **Secrets in private files are encrypted with a primary password** where no system keyring answers. Existing plain
  stores keep working (a note says how to encrypt them); the first secret kept in the files asks for a password, or
  `secrets set NAME --plain`.
- **Shared-service wildcards** (`*.blob.core.windows.net`) were always refused; they are now allowed after your
  confirmation (`--allow-shared-wildcard`, `-sw`), still refused in `high` and `paranoid`.
- **The session file views list logins and keys** (marked *Login or key*); their text only with `--show-secret`.
  `hide_secrets` (Settings > Privacy) brings back the old hiding; `session export` leaves them out by default.
- **`resume NAME --mount SOURCE:DESTINATION` without `:ro` or `:rw` is read-only**, as the Board makes such a mount.
- **`mcp add --mount /work=/work` is refused:** HOST in `--mount` is a folder of the machine, never the sandbox's view.
- **`--budget` needs the connection proxy** (refused with `--no-proxy`).
- **The loop guard's turn limit (`steps`) is 150, not 40**, for `--llm` starts; your own value still wins.
- **Qwen Code:** a session ends after 120 turns (`model.maxSessionTurns`); with `-D` it runs in YOLO mode.
- **`sandbox-ai mcp` names itself `sandbox-ai mcp:`** in every message (scripts that look for `sandbox-mcp:` should
  look for both).
- **The image recipe `tor` is gone:** Tor networking needs nothing in the agent's image; the Tor container carries it.
- **A WireGuard or Mullvad profile runs in one sandbox at a time** (a second start with it is refused and names the
  holder); a team's `--vpn` is one choice for all members, and a start lends its tunnel to its own MCP servers.
- **App:** the section *Insight* is *Monitoring*; *Show explanations* (Settings > Appearance) is off by default, so the
  pages' intro lines and hints are hidden until you turn it on; the session page's buttons are icons (*Show button
  texts beside the icons* adds the names); a closed terminal tab is not opened again at the next start of the app.
- **Update checks:** the default update mode is `notify` - one check a day, a newer signed release announced once.
  `sandbox-ai update mode off` checks nothing unless asked.

## Security and the network

- **Secret guard (egress DLP):** the connection proxy searches every request it opens - URL, headers, body - for the
  values a start hands out (`--secret-env`, secret-looking `--env`, Git tokens, MCP secrets), also URL-, JSON-, hex-,
  base64- and gzip-encoded, and for known token shapes. Sent to a host they were not given for: reported by default,
  asked or refused by a ruleset's `"secrets"` section; `high` and `paranoid` refuse handed-out values. Nothing is
  redacted or changed, and no value is ever shown. `--allow-send WHAT@HOST`, `sandbox-ai secret-guard
  allow|forget|list`.
- **Package guard:** every download from npm, PyPI, crates.io and Go's module proxy is judged before it is fetched -
  known malicious (OSV `MAL-...`): refused; younger than 14 days: asked; a name the registry does not know or younger
  than 30 days: recorded (asked in `high` and `paranoid`). No package name leaves the machine: the malicious list is an
  offline copy (`sandbox-ai packages sync`; `packages sync --osv` builds it from OSV's dumps). `sandbox-ai packages
  check|allow|forget|list`, `--allow-package SPEC`, `--no-package-guard`.
- **Workspace checkpoints:** `sandbox-ai checkpoint restore NAME` puts a start's workspaces back as they were when its
  last start began - every file, link, mode and the project's own `.git`, so a `git reset --hard` or `rm -rf` of the
  agent is undone. Taken at each start, every N minutes (`--checkpoint-every N`) and by hand (`sandbox-ai checkpoint
  RUN --label TEXT`); `checkpoint list|show|diff|delete`; limits `checkpoint_days`, `checkpoint_count`,
  `checkpoint_gb`. Kept in sandbox-ai's own state, out of the agent's reach. App and web: *Checkpoints…*.
- **`--allow-domain DOMAIN` (`-ad`):** a domain and every name below it, exactly `--allow-host DOMAIN --allow-host
  '*.DOMAIN'`, with the wildcard's checks; also for `net allow` and `revoke` during a run.
- **Wildcards below a shared service** (`--allow-shared-wildcard`): allowed after you confirm the risk, marked as a risk
  in `net show` and the report; refused in `high` and `paranoid`, by the policy key `forbid_shared_wildcards`, and
  always for top-level domains and public suffixes.
- **Supply-chain hygiene:** a hidden-text checker (Unicode tag characters, zero-width and bidi characters, instruction
  phrasing, `curl | sh`, ...) on kits, plugins and the workspace's instruction files; `sandbox-ai scan PATH...` runs it
  alone. MCP tool definitions are pinned per project: a new or changed tool is a question of the kind `mcp-tools`
  (`sandbox-ai mcp tools [NAME] [--forget|--repin]`).
- **Ready-made rulesets**, opt-in with `--rules builtin:NAME`: `github-persistence`, `destructive`,
  `mcp-no-credentials`, `secret-files`; every rule asks. Rulesets can run in audit mode (`"mode": "audit"`;
  `sandbox-ai rules audit` sums up what they would have decided).
- **The workspace review after each run:** Git hooks and configuration, editor and agent folders, `package.json`,
  `Makefile`, CI workflows and instruction files changed by a run are named with their diff. `sandbox-ai workspace
  review RUN --keep PATH | --restore PATH --yes`; app: Activity > Workspace review.
- **`--hide GLOB`:** an empty read-only file or folder over each workspace file a glob matches (also for folders added
  with `workspace add` during the run).
- **Rules for every agent's own tools:** tool rules and kit hooks now hold for Qwen Code, Hermes, Pi, OpenCode 2,
  DeepSeek Harness, Letta Code and Goose through each agent's own hook or plugin API, with one ruleset for all agents;
  the mode `paranoid` starts them. OpenHands and nanobot stay refused with tool rules, saying what is missing.
- **Approvals:** a tool call's question shows its arguments in full (up to 64 KiB, credentials redacted;
  `sandbox-ai approvals show ID`); a larger call is refused without a question. An answer is bound to the call it
  showed. `approvals list --state open|timeout|allowed|refused|all`; `approvals allow|deny|ask-again ID` change any
  answer.
- **`runtime.py --untrusted -- COMMAND`** in the sandbox runs a test suite or install script confined by Landlock: no
  access to the agents' logins, transcripts and HOME credentials, HOME read-only, an environment without the run's
  secrets. `sandbox-ai doctor` has a line for it.
- **Isolation, checked and recorded:** the proxy drops its bounding set and installs the sandbox's filter on itself; an
  administrator's policy key `lsm` starts every container under an AppArmor profile or SELinux type; `isolation.json`
  in the log directory records kernel settings, capabilities, filters and mounts (`--dry-run`: `"isolation"`).
- **Relay sockets bound before the sandbox starts:** `sandbox-ai attach` and `shell` connect to sockets the sandbox
  cannot replace; the hook socket is the agent's user's alone; the services the sandbox reaches are bounded.
- **Login callbacks** go only to the socket you were asked about, and the one-shot catcher takes only the callback
  that carries the login's `state`.
- **Redaction in logs:** an assigned secret's value is masked up to the next white space or quote (it ended at `;`,
  `&`, `|` or `)` before); logs also mask Hugging Face, Google API, npm, PyPI and Stripe tokens.
- **An MCP server under Bubblewrap** no longer sees sandbox-ai's environment through `/proc/1/environ`; a catalog entry
  may run the server itself as PID 1 (`"pid1": "server"`).
- **Tor:** a link in the terminal of a Tor run is never opened on this computer (Copy link instead; behind a VPN after
  a warning); a start waits for tor's bootstrap and its first SERVFAIL; `.onion` lookups and every lookup behind Tor
  give IPv4 only; `net cut` behind Tor cuts tor's DNSPort too; every agent is told from its start how the run reaches
  the network.
- **VPN:** a start lends its WireGuard, Mullvad or Tailscale tunnel to its own MCP servers (one key, one tunnel;
  `net cut` stops them too); MCP servers behind a VPN start again; teams get `--vpn PROFILE` and `--member-vpn
  AGENT=PROFILE` (OpenVPN in several members only with `--allow-shared-openvpn`).
- **The kill switch reaches an orphaned run**, and a sandbox never runs on without its supervisor: on a nearly full disk
  the run now fails closed and says so.

## Agents and harnesses

- **Eight new agents, each reviewed first and marked "not live-tested yet"** (a note, never a refusal): Hermes Agent
  (`sandbox-ai hermes`), Qwen Code (`sandbox-ai qwen`), DeepSeek Harness (`sandbox-ai dsh`), Goose (`sandbox-ai
  goose`), OpenHands (`sandbox-ai openhands`), nanobot (`sandbox-ai nanobot`), Letta Code (`sandbox-ai letta`), Pi
  (`sandbox-ai pi`) - and OpenCode 2 as an agent of its own (`sandbox-ai opencode2`), while `sandbox-ai opencode` stays
  OpenCode 1. Build each with `sandbox-ai build AGENT`.
- **Each new agent:** a release at least 14 days old checked against its digest or hash-locked dependencies, no
  self-update, telemetry always off and refused by the proxy, its managed configuration read-only, and features that
  reach the network off until turned on with its own switch (`--hermes-enable`, `--qwen-enable`, `--goose-enable`,
  `--nanobot-enable`, ...), each opening only its own hosts.
- **`--with` for every agent and every agent as a team member:** the team image comes in layers
  (`sandbox-ai build team --with hermes,qwen` or `--with all`), and a start picks the image with exactly its agents.
  `--with` takes `AGENT[,AGENT...]` and repeats.
- **Presets for every agent:** `default-AGENT` (sandbox-ai's defaults and nothing more), `coding-AGENT` (the maker's
  model) and `AGENT-local-llm` (a model of your own server with the loop guard), in the gallery's category *Agents*.
- **`sandbox-ai shell NAME`:** a shell of your own in a running sandbox beside the agent, under exactly the agent's
  rules; `shell NAME -- COMMAND` runs one command and returns its exit status, `-n` without a terminal. Noted in the
  activity timeline; the app and the web have a *Shell* button.
- **Session bridges:** `sandbox-ai bridge add A B --allow CAP[,CAP...]` lets one running session message another, ask
  its agent, read or write files below a granted path (every write asked, with its diff) or watch it as an observer
  (`--observer-actions alert,hint,net-cut,pause`). A broker on the host, never between the pods; only you make or
  widen a bridge; peer content is untrusted. Bridges across hosts too (`bridge add lab1:a lab2:b`).
- **Cairn as a part of its own (`--cairn`):** its board in the session's browser, the session's agents its workers,
  in a container of its own in the pod; presets `cairn-pentest-board` and `cairn-local-llm`. The dispatcher is paused
  after repeated failed tasks.
- **`--show-thinking on|off` (`-sk`)** for every agent with a switch for it (refused, with the reason, where there is
  none).
- **Cloud models per agent:** `sandbox-ai models [--agent AGENT] [--json]` lists the models each agent can use with its
  login or key and the effort levels each takes; an `--effort` a listed model does not take is warned of. Codex takes
  `none`, `max` and `ultra` too.
- **Kits from your agents' own setup:** `sandbox-ai kits host-list`, `host-show ID` and `host-import ID... --kit KIT |
  --project DIR` bring skills, commands, subagents and memory of your own agents into a kit or a project's memory;
  secret-looking lines refuse the import unless `--allow-secrets`. Also from a host (`--host HOST`).
- **Skills and plugins for a running sandbox:** `sandbox-ai kits attach START (KIT | --skill DIR | --command FILE |
  --agent-file FILE)`, `kits detach`, `plugins attach START NAME@MARKETPLACE`, `plugins detach` and `kits restart-agent
  START`; each answer says what the agent needs to take it up.
- **Plugins for Codex and OpenCode 2** from kits, read from each pinned release's plugin system.
- **Logins of sessions:** `sandbox-ai login --status --sessions` shows each session's login (account, kind, expiry, a
  fingerprint - never a token); `login AGENT --from-session NAME` makes it the central login; `--auth-from-session
  NAME` (`-as`) gives it to a new start; `sandbox-ai login give RUN [AGENT]` puts a login into a running sandbox.
- **A session's memory and files:** `sandbox-ai session memory NAME`, `session files NAME` (the agents' own session
  files, shown as a conversation; `--search PATTERN`) and `session export NAME OUT.tar.gz`, read only, also for a host.
- **Codex's device sign-in by itself:** an interactive Codex start without a login runs `codex login --device-auth`
  first; the app opens the device page and shows the one-time code in a small window (never behind Tor or a VPN).
- **Every agent waits long enough for an MCP call** (the server's `tool_timeout`, `mcp set NAME --tool-timeout
  SECONDS|default`).
- **Hermes** never asks about telemetry at its start; it is refused below 64k context with a local model.

## Local models (LM Studio, Ollama, llama.cpp, vLLM)

- **Model x harness profiles:** a start with `--llm NAME:MODEL` applies the settings measured for that model in that
  agent (sampling, context window, loop guard steps, the agent's own switches) as the lowest layer under everything
  you set; the start says it in one line. `--no-llm-profile` (`-nl`) switches it off; `sandbox-ai llm profiles [MODEL]
  [--agent AGENT]` lists them with what works, what fails and what is not known.
- **A traffic light per model and agent:** green verified, yellow partly working, red does not work, grey not tested -
  in `sandbox-ai llm models NAME` (column SUPPORT), the app's model lists and the web, always with a symbol and words.
- **Use cases:** `sandbox-ai llm recommend [USE_CASE] [--llm NAME] [--agent AGENT]` lists your servers' models as model
  x harness pairs per use case, best first, with models marked unsafe for untrusted input named apart; `sandbox-ai
  AGENT --llm SERVER --use-case NAME` (`-uc`) picks the model and settings, never an unsafe one by itself. The Board,
  the Start page, the wizard and the web offer *Use this pair*. `llm set NAME --memory GB` for the fit check.
- **The LLM traffic log:** what an agent and its model exchange, one record per request beside the connection log
  (`--llm-traffic llm|all|off`, `-lt`; `--llm-traffic-limit MIB`). `sandbox-ai llm traffic [RUN|--session NAME]`
  shows it as a chat; `sandbox-ai report --llm-traffic`; the app's page Monitoring > LLM traffic.
- **Models on the server:** `sandbox-ai llm loaded NAME`, `llm load NAME MODEL [--context N] [--ttl S]` and `llm unload`
  (refused while a running sandbox uses the model, unless `--force`); the app's *Models on the server…*. A start says
  when its model is loaded JIT and loads it explicitly when nobody else uses it.
- **The server's other models in the agent:** a start offers every model of its server, `--llm NAME:MODEL` staying the
  default; `--llm-models MODEL,MODEL` (`-lo`) limits them, and the proxy refuses others.
- **Advanced settings per model and server:** `keep_alive`, `ttl`, `flash_attention`, `offload_kv_cache_to_gpu` and
  `stream_idle_timeout`, each offered only to the kind of server that takes it; `llm params` names what only the
  server's own start sets. The app's "Parameters…" is now "Advanced settings…".
- **The agents wait for a slow model:** at a server of your own they wait up to an hour for the first token instead of
  sending the whole request again; LM Studio loads with `parallel: 1`, so the prompt cache stays.
- **Fixes from the local-model research** (eight rounds on a real LM Studio): a step after the loop guard's note no
  longer costs a full prefill; Codex's MCP tools and shell commands work with local models; Claude Code compacts within
  the model's window and leaves out tools local models never use (`--llm-tools`); every family's profile caps one
  answer (`max_tokens`); an answer the agent gives up is cancelled at the server; agents are told the window Ollama
  really serves.
- **What the research measured (rounds 7 and 8):** every model x harness status is now derived from the graded runs (`sandbox-ai llm profiles`; the matrix in `docs/LOCAL_MODELS.md`): 31 pairs are verified - Ornith-1.5-35B-A3B in all nine harnesses, Ornith-1.5-122B, Qwen3.8-Flash-Next and Qwen3-Coder-Next in most. Laguna-S-2.1, Qwen3.6 and Muse Glimmer ran a planted instruction (an MCP ticket's command, `.env` sent out) and are marked never for untrusted input: `llm recommend` and `--use-case` never pick them for it.
- **The loop guard** sees more repeats (Codex, DSH, Hermes, changing descriptions, guessed calls that all fail; the
  `failures` and `rejected` layers) and can keep progress notes (`loop_guard.progress_notes`, off by default).
- **OpenRouter for every agent:** `sandbox-ai llm add openrouter -k openai-compatible -u https://openrouter.ai/api/v1
  -s SECRET -m MODEL`; only openrouter.ai below `/api` is opened.

## MCP servers and the catalog

- **New in the catalog:** jadx and cfr (Android and Java reverse engineering, `network: none`), smali and frida (the
  Android preset), and axross (file tools on a mounted folder and on axross's saved SFTP connections); some are pending
  until the catalog's CI publishes their digests. Playwright MCP is in the signed catalog.
- **Variables that are no secret, optional ones, secrets of another name:** `sandbox-ai mcp add|set NAME --env
  NAME=VALUE | NAME | NAME@SECRET`; a start's own `--mcp-env NAME:VAR=VALUE|NAME:VAR@SECRET` (`-mv`). The app's MCP
  Properties show a table of the server's variables.
- **Everything a start's MCP servers need is checked first**, every problem at once with its fix; a server running
  with another definition gets an instance of its own instead of ending the start late.
- **`sandbox-ai mcp copy NAME... --from HOST --to HOST`** copies servers between hosts (`--attach RUN`); a catalog
  server is re-added from the target's own signed catalog, secrets go by name only. App: *From another host…*.
- **Network kinds:** `full` (internet, no LAN), `allowlist` (only the entry's hosts), `lan` (opt-in, with a warning),
  `none`; `--allow-private CIDR` and `--allow-tcp IP:PORT` open a part of your network to a server.
- **Adding an MCP server never ends a running session:** a restart is checked before the stop, `mcp add` refuses a pull
  without room, and a stop on purpose says what stopped the run.
- **An MCP server that crashes on a tool call** answers each open request with an error at once; its log reader goes on
  after a full disk.

## The desktop app

- **System monitor** (Monitoring): every run's CPU, memory, disk IO, network and processes, recorded every 10 seconds
  (`monitor_interval`); gauges, charts from 15 minutes to 30 days, sparklines, warnings with suggestions (raise a
  limit, stop an idle run), cost per run with budgets; *Go to Terminals* and *Go to Sessions* from a run. On the
  command line: `sandbox-ai top` and `sandbox-ai stats usage`.
- **The sandbox's own browser:** *Browser* on the Sandboxes & sessions page shows the live browser of a `--browser`
  run as a tab beside its terminal (a VNC client of the app's own over a Unix socket; nothing listens on TCP).
- **Board:** *Save* beside *Save as preset…*; Team, Bridge, Browser and Cairn parts; an icon for every kind of part;
  list options as one compact field (kind, value, *Add*, chips); seldom-set options folded under *More options*;
  devices detected on the board's host in a drop-down and added while a start runs; the Service part offers
  sandbox-ai's own service images (built when needed); *Export…* and *Import…* of a board.
- **File manager:** this machine, sandbox-ai's hosts, their sandboxes and remote systems in either pane, so copy and
  move go host to host; drag and drop for every pairing; a search below a folder with glob wildcards (`*`, `?`,
  `[a-z]`, `**`) and optional content (Ctrl+Shift+F); *Save as…* in the editor; many review passes for agents' files
  (never executable when copied out, links never followed, hung file systems that no longer freeze the window).
- **The pages follow the Sandboxes page's host**, and what the app does for a start on this machine it does for a start
  on a host (secrets and Git logins given, approvals, the Board's MCP part, LLM traffic, reports).
- **Sandboxes & sessions:** tabs *Sessions & sandboxes* and *Schedules*; icon rows; *Disk usage…*, *Optimize…* and
  *Storage…*; *Checkpoints…*, *Memory…*, *Session files…*, *Export…*.
- **Credentials:** *Edit…* on every tab; *Give to a running sandbox…* for every kind that can be given, also to a
  sandbox on another host; a tab *Given to sandboxes* with *Revoke…*; *Logins of the sessions*.
- **Dialogs** keep what you typed after Cancel or a refusal; every dialog and window is large enough to use and opens
  where you expect it; an undocked panel is centred and fits; tables size their columns to their content.
- **After an update, the new app:** a start of the app asks an older running app to quit and takes over;
  `sandbox-ai-app --version` names the app, its folder and the sandbox-ai it loads.
- **Before a start:** a session name that is taken is said with *Attach to it*, *Stop it and start*, *Start as* or
  Cancel; an agent without a login on the start's host offers *Log in now*.
- **Look and feel:** a theme *hacker (neon)*; the keyboard focus visible on every control; the app's own icon; short
  notices (toasts) for what only says that something is done; the app loads Qt's German translation.
- **Videos about the pages** (German, spoken, with subtitles): Help > *Videos about the pages*, or the release asset
  `sandbox-ai-videos.tar`, which the app downloads and checks itself when first asked.

## The web interface

- **New pages and views as in the app:** System monitor, Approvals as one table with tabs, Schedules, Checkpoints,
  Memory and Session files (with a search), Workspace review, MCP tool pins, phone notifications, the cloud models and
  effort of every agent, a *Use case* field with recommended pairs.
- **A login without TOTP if you want one:** `sandbox-ai web user add NAME --no-totp` (also `reset`); TOTP stays the
  default, and such a login is warned about at every login and when `web serve` starts.
- **Secrets under the primary password** (unlock, lock, set) and *Send to another host…*; *From another host* for MCP
  servers; kits from the agents on a host; board *Export* and *Import a board…*.
- **`web serve`** says its address and fingerprint at once into a log or pipe, is reached at IPv6 host names, and says
  when its certificate does not name a name it serves (`sandbox-ai web cert --renew ...`).
- **The team start** offers every agent, and the add form of an MCP server takes values and named secrets.

## The command line

- **`sandbox-ai schedule`:** runs on a timetable (`--every`, `--at`, `--cron`) or when a branch moves (`--on-push
  REPO`), in the agent's one-shot mode, with a report of each run (`schedule history`, `schedule report`). Questions
  at night: `--ask off` by default; a time limit per run (`--limit`, 60m); `--commit BRANCH` and `--push REMOTE` after
  the privacy check. `schedule enable` installs a systemd user timer or a LaunchAgent.
- **Spend and budgets:** the proxy counts every model request's tokens and prices them (`sandbox/prices.json`, your own
  with `spend prices set`); `--budget USD` (`-bu`) per start and `sandbox-ai spend limit set` per day or month; at 100 %
  the next request is refused (HTTP 402) and `sandbox-ai spend raise RUN USD` lets it go on. Local models cost 0,
  Claude and ChatGPT plan logins show *subscription*. `sandbox-ai spend`, `spend run RUN`.
- **Phone notifications:** `sandbox-ai notify add|list|remove|test|link|events` sends questions, canary alarms and,
  when chosen, safeguard events, budgets, updates and run ends to ntfy, Telegram, WhatsApp or a webhook - from the
  host, tokens as secret names, no answering from the phone.
- **Boards as one file:** `sandbox-ai board export` writes a board or a session as a bundle (`--images` for offline
  use; never a secret's value); `sandbox-ai board import` shows its plan first (`--check`) and recreates what the start
  needs on another machine.
- **Remote folders:** `--workspace sshfs://[USER@]HOST[:PORT]/PATH`, `--mount sshfs://...:DEST:ro|rw` and `workspace add
  RUN sshfs://...`; also `nfs://` and `smb://` (Linux). The agent never gets `/dev/fuse`, a key or the connection.
- **Disk use:** `sandbox-ai gc --usage [--detail]` says what sandbox-ai keeps, biggest first; `gc --check` makes a plan;
  `gc --caches`, `--build-output`, `--toolchains`, `--transcripts DAYS`, `--compact-transcripts DAYS`, `--pack`,
  `--images[=unnamed|old|prune]`, `--logs-older-than DAYS`, `--only`; automatic rules `storage_*_days`.
- **Devices:** `sandbox-ai devices scan [--json]` lists what a sandbox could be given (USB by identity, serial ports,
  cameras, render nodes, GPU kinds), and what is refused with why.
- **Root sees every user's starts:** `sandbox-ai list --all-users` and `--user USER`; `stop`, `logs`, `report` and
  `list --history` take `USER:NAME` for root.
- **Images of other distributions:** `sandbox-ai images os NAME` and `images derive NAME --from IMAGE --add-os PKG ...`
  for Alpine, Fedora/RHEL, Arch and openSUSE images of your own; `images extend --add-os`; a list of registries to
  browse in the app; `images build-image NAME --builtin TEMPLATE` and `images templates`.
- **More:** `sandbox-ai build all` builds every image and goes on after a failure; `sandbox-ai build A B C` builds each;
  commands with subcommands list when called alone (`sandbox-ai approvals`, `mcp`, `vpn`, ...); `sandbox-ai logs NAME`
  takes a start's name; `secrets rename OLD NEW`, `git-logins edit`, `publish-logins edit`, `vpn set NAME --...`;
  `secrets send NAME HOST`; `session status NAME`; `list --folders`; tab completion for every command and option.

## Installs and updates

- **Every kind of installation updates itself** from a signed release (GitHub by default, a Gitea or Forgejo with
  `--source URL`): install.sh's installations as before, and now the `.pyz`, the AppImage, the macOS app and pip or
  pipx installations replace themselves (`sandbox-ai update`, `update --install`, `update --rollback`).
- **Update modes:** `sandbox-ai update mode off|notify|download|auto [--at HH:MM-HH:MM]`; `auto` installs only in its
  window and while nothing runs; `sandbox-ai hosts update NAME --mode MODE` for a host. App: Settings > Updates.
- **A release is complete or it is not published:** every file listed in one place, checked against the signed
  `SHA256SUMS`; `scripts/release_check.py 0.1.188` says per file whether it is there and works.
- **`sandbox-ai uninstall`** removes the installation it runs from, with a table first; `--purge` also the data,
  `--secrets` (with `--purge`) the secrets; running starts refuse it unless `--stop-running`. Never workspaces or
  mounted folders.
- **PyPI:** one package `sandbox-ai-app` (the command line and the web interface; `[gui]` adds the desktop app with
  PySide6 pinned per Python version).
- **Shell setup:** a system installation puts the completion scripts in place; `sandbox-ai completion install` writes a
  marked block into `~/.bashrc` and `~/.zshrc`; an install or update says `source ~/.bashrc` when it changed something.
- **`sandbox-ai doctor`** checks the PATH (*Commands in PATH*), secrets, MCP network, isolation, sshfs and the update
  mode; install.sh says at its end what still keeps you on another version.
- **Hosts:** `sandbox-ai hosts update NAME --from-here` for a host whose sandbox-ai is too old to update itself.
- **The live check:** `scripts/live_check.sh` runs on your own Linux machine (or Mac) what the development sandbox
  cannot run and writes one redacted report (docs/LIVE_CHECK.md).

## Stability and performance

- **Three stability rounds:** the proxy no longer fails new connections past about 250 at once (descriptors over
  1024); incomplete TLS hellos no longer hold its threads; damaged `run.json` and deeply nested JSON files count as
  damaged instead of a traceback; a full disk or SIGHUP no longer skips a run's clean-up; dialogs no longer stay in
  memory after closing; the segmentation fault of the app's soak tests was traced to the soak's own watchdog.
- **Performance rounds:** HTTP rules are looked up by name (a request with 2,000 rules from 0.54 ms to 0.034 ms); the
  traffic log no longer stalls the proxy; a start asks Podman about all its images at once and brings MCP servers up
  side by side; names are looked up in one container; certificates are made once per host.
- **Logging:** the launcher keeps `~/.local/state/sandbox-ai/launcher.log` (what was asked, decided, run and why it
  ended, never a secret); `SANDBOX_AI_DEBUG=1` adds every outside command; the app's log window and *Copy for a bug
  report*.
- **Nothing lost when logs rotate:** the connection log, `activity.jsonl` and the monitor's series rotate and compress
  while a run runs, and every reader reads the rotated parts.
- **A full file system is named, not assumed:** errors say which file system, how much is free and how many inodes; a
  pod Podman cannot create is said in words; a kept start whose folder is gone says which.
- **Leaks:** a long run's launcher stays small; `sandbox-ai list` with many kept starts no longer reads the log state
  again per start; the app frees closed windows, tours and chats.
- **Services** with in-memory data folders (postgres, redis) start again; `--nested-containers` gets its own IPC
  namespace for crun's mqueue.
- **Checked on GitHub's runners as an ordinary user:** the first CI run of this release found what a non-root machine
  with long temporary paths meets. Fixed: on Python 3.12.7 and newer `sandbox-ai completion <TAB>` offered nothing for
  the completion command's own arguments; `sandbox-ai update --check` of a system installation failed for every user but
  root (`install.sh --check` now needs no root, installing still does); Letta Code's image could not start the agent by
  its name (the start script now looks it up on PATH), and a first start of Letta Code with `--llm` or `--model` and
  `--mcp` lost the MCP servers (the model's name was taken for a subcommand, and Letta Code made a second agent without
  them); a memory, CPU or process warning was lost when the memory watch had not found the run's cgroup; Cairn's relay
  no longer needs a `/work` folder for its start check; in the app, a board part's long project path keeps the folder's
  name whole in every theme, and the one-time code of a device sign-in is large in every theme again (a theme's style
  sheet had set it to 10 pt). The tests themselves now run as an ordinary user too (root-only ones say why they skip).
- **Independent reviews, deep test rounds, analysis rounds and audits** of every new feature, with every live bug
  turned into a regression test first; the complete notes list each finding.
