# sandbox-ai 0.1.90

- **The app's crash on a terminal tab, found and fixed:** a terminal tab opened while the app had an event filter on
  the whole application ended the app with a segmentation fault - right after the app started (its pages were still
  made in the background under such a filter: Board > Start soon after starting), or while the open questions were
  shown as a panel. The app now never filters the whole application (a test makes sure).
- **Update now…** in the app when a newer sandbox-ai is there (with `sudo` for an installation for every user), then
  **Restart the app**.
- **One Start** on the Board and the Start page: where (the app or a terminal window) and **as a session** (on by
  default, a codename unless you type a name) - it keeps running when its terminal or the app closes.
- **Credentials:** a Git login is given to a sandbox that runs (its menu or Give to a running sandbox…).
- **Esc** closes a panel floated out of the window.
- **Tor has an image of its own** (`sandbox-ai build tor`), apart from the VPN software (`sandbox-ai build vpn`:
  WireGuard, OpenVPN, Tailscale). wireguard-go is pinned (v0.0.20231211) and optional: without Go's module proxy the
  VPN image still builds, and a WireGuard profile says what is missing.
- **`sandbox-ai build` when names do not resolve in a build container** (every image failed with "Temporary failure
  resolving deb.debian.org"): checked first, then built with the host's network when only that resolves, or stopped
  with what to look at; `--dns IP` is kept as given.
- One prompt per question: the app says in its log window when it cannot tell the launchers that it shows the
  questions; `run.json` names the sandbox-ai version of a run. Runs started before 0.1.86 keep asking on their own
  until they are restarted.
