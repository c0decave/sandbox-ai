# sandbox-ai 0.1.76

- **A workspace added while the sandbox runs:** `sandbox-ai workspace add [RUN] DIR [--ro]` mounts a host
  directory at `/workspaces/<name>` without a restart, with every check of `--workspace` at a start;
  `workspace list` and `workspace remove [RUN] DIR|NAME [--force]` (a strict unmount, the sandbox frozen for the
  check, refused while the agent holds a copy in a namespace of its own). A session keeps it for its next start
  (not one added `--ro`).
- **Host wildcards:** `--allow-host '*.example.com'` (and `sandbox-ai net allow`) allows every name below a
  domain; each one is opened as it is looked up, answered on the host, and the agent's first try works (256 names
  per wildcard and run, more are asked). Public suffixes and hosting services (`*.co.uk`, `*.github.io`,
  `*.amazonaws.com` ...) are refused, and so is a wildcard with `--dns`/`--nameserver` (lookups would pass the
  sandbox's DNS stub).
- **Keep what a run was given:** `sandbox-ai net show [RUN] --keep` writes everything opened during the run
  (names, wildcards, addresses, DNS, host ports, devices, added workspaces; never Git tokens) into the project's
  trusted `.sandbox-ai.json` of the first workspace.
- **Memory:** the watch sets `memory.high` at 92 % of the limit (the kernel slows the sandbox down instead of
  ending a process in it) and also relieves a sandbox stalled by memory (PSI); a lifted limit lifts it again.
- **The app, local and remote in one place:** the Sandboxes page lists the starts of your other hosts beside this
  machine's, with Host and Memory columns; attach, pause, resume, stop and delete run on the start's own host, each
  confirmation naming it. The Hosts page never shows another host's starts under the chosen one, refreshes itself,
  and asks before Allow; names a host sends back are checked before they become arguments there.
- **The web interface:** approvals keep their rows and ask before Allow, a forgotten tab logs out, nobody can lock
  a user out from outside, terminals say why they ended, the audit log names what changed, at most 64
  connections; host wildcards are accepted.
- **Names:** host names are case-insensitive (`--allow-host Example.org` is `example.org`), and `net allow`
  refuses names outside ASCII as a start does (give their `xn--` form).
- `sandbox-ai stop NAME` ends every kind of start; `sandbox-ai net stop` is its older form.
- **Fixes:** a symlink loop the agent makes in a PATH directory of the workspace no longer ends the launcher
  before the login write-back and the privacy check; the run registry tells a reused PID from the run's; the file
  log walks by descriptor (no symlink race) and survives very deep trees; `net` commands on a paused or busy
  sandbox say so instead of a traceback; concurrent pins and login-sync records are no longer lost; NAT64
  addresses never count as public.
- **Tests:** they never touch the real HOME (`tests/home_guard.py`); a session fails if a real login file
  changed.
