# sandbox-ai 0.1.79

0.1.79 carries everything listed for 0.1.78 (docs/releases/v0.1.78.md; 0.1.78 was never published: it only marked
the state installed from the repository while the reviews went on), and on top:

- **Version numbers** go up with every larger change from now on: x.y.z → x.y.(z+1); after x.y.249 comes x.(y+1).0,
  after x.49.249 comes (x+1).0.0 (`scripts/bump_version.py`).
- **LLM servers: what they have loaded and use now.** `sandbox-ai llm status [NAME] [--json] [--watch SECONDS]` reads
  every registered server at the same time (5 s per request; one that is down or hangs holds up no other) and shows
  the loaded models with their size and the memory they take, and what its API reports: Ollama the VRAM and RAM of
  each loaded model (`/api/ps`), vLLM the KV cache and the requests running and waiting (`/metrics`), llama.cpp its
  slots and with `--metrics` the requests (in router mode the memory per device and the devices' total and free),
  LM Studio the loaded instances (`/api/v1/models`, 0.4 and later; its models' sizes too). What an API does not
  report is said ("not_reported"), never guessed; the host's total RAM/VRAM is not reported by these APIs.
  `wizard models --status` adds it to a test before registering. The app and the web show it after Test connection,
  as a line per server on the LLM servers page (read in the background every 20 s while it is shown) and beside a
  start with `--llm` (app: below the Sandboxes table for the selected start; web: LLM status in its row); `sandbox-ai
  list --json` names a start's `--llm` ("llm"). An older host is told to update.
- **App and web: every model of a server is offered.** The Model choice beside the agent (Start page, Board) and a
  preset's LLM value listed at most 30 models of a server; now all of them, in a popup that scrolls (20 rows) and that
  typing filters (any part of the name, any case); the dialog's default model and the wizard's model too. The web's
  model choice of a new start lists every model with its size and whether it is loaded, and has a filter.
- **App, Board**: the right mouse button drags the view like the middle one (a right click without moving opens a
  menu: add a part there, select all, fit, zoom 100 %, arrange, undo/redo; on a part Set up step by step…, What is
  this?, Delete; the menu key too). A click no longer snaps every part to the grid and adds a "Move" to Undo (the
  content jumped); only the left button selects and moves, and only the parts it moved snap. Middle-button panning
  works (it never did: Qt hand-drags with the left button only). A part's text wraps to at most three lines inside
  it (the part grows, "…" when more is left, all of it in the tooltip and the inspector) instead of running over its
  edge. Selecting a part brings back the inspector's panel when it had been closed (floating or docked).
- **App: the window keeps answering while work runs.** A kit change (Add plugin, a marketplace, a skill, a hook;
  cloning a marketplace takes a while), a host's update or installation show a busy bar naming what runs, a Cancel
  that ends the command with everything it started, and what sandbox-ai writes as it comes; the outcome is said in
  the page (wrapped, plain text), one change runs at a time and a second click starts nothing. The status bar says
  which pages have work running ("Running: Kits & plugins…"). What still ran on the window's thread now runs in the
  background: the registry reads that may ask Podman about ended runs (the project switcher and menus, the Files
  page's folders, the Activity page's sources, the Board's live rows, Start at login); the approvals' scan and the
  question when quitting read only the registry's files and /proc; the check whether Chromium's sandbox can start
  (before each terminal tab, a child process) runs in a thread while the window goes on. Tests: each long action
  clicked against a backend that takes 2 s (the window must answer every 200 ms), every button of every page
  clicked with every slow backend call faked (none may run on the window's thread), and an AST check that holds
  every slow backend method, in every module of the app, to the background.
- **App: buttons are actions, toggles look like toggles.** A clicked button no longer looks pressed afterwards
  (Home on the Files page: some themes drew the focused button as pressed; focus is now a border there, and the
  Files page's buttons take no focus from a click). "Details" and "Advanced options" are disclosures with an arrow;
  the "+" menu's projects are actions (an open one says "(open)"), the project switcher a radio choice. The Files
  page's two panes split half and half and keep the division you drag.
- **App and web: the names of secrets and VPN profiles are offered where a field takes one.** Each field that takes
  the name of a stored secret or of a VPN profile is a list to choose from with the chosen host's names (read in the
  background over SSH for another host: `secrets list`, names only, never a value; `vpn list --json`), typing a name
  that is not there yet still works: the VPN profile's key, password, account and bridges secret, an LLM server's API
  key secret and VPN profile (its Test connection too), the wizard's model server, "Use a stored secret" of a Git or
  publish login, an identity's logins, MCP add and start `--vpn`, the Board's `--vpn` (and its step-by-step guide),
  `--secret-env`, `--api-key` and `--git-token-secret` on the Start page and the Board ("+" adds one; HOST= and URL=
  lines are completed), and a sandbox-ai preset's secret value. Another host chosen reads its names (a late answer for
  the one before is dropped); an older host that cannot list them leaves the field typed in, the tooltip says why; a
  secret or profile added or removed on the Credentials page reaches every open field. The web interface offers the
  same through a list of suggestions (VPN, LLM servers, MCP servers, identities, a preset's secret value).
- **App, Board panels**: the inspector (properties) waits as a narrow strip at the right edge of the board and slides
  out when a part is clicked (Esc, a click on the empty board or its arrow slide it back); View > Panels >
  Properties as a separate window makes it a window of its own that opens on a click instead (remembered). The
  security score and the findings are a panel of their own, closed until asked for (the score's button above the
  board or View > Panels), and no longer move with the inspector.
- **App, help on hover and the (?) setting**: "Show the (?) help buttons" off now removes every (?) of the app, also
  the one painted in each row of the Board's parts list (it stayed, and clicks there still opened an explanation);
  a table no longer keeps room in its last column title for a (?) that is off. Terms explain themselves on hover, with
  or without the (?)s: the navigation (what each page is for), every setting and Settings tab, the labels and column
  titles that have a help text (Approvals, Sandboxes, Connections, Files, Kits, MCP, LLM, VPN, Images, Credentials,
  Identities, Teams, Hosts), the labels of the controls with a (?), group titles (over the title only) and the
  dialogs' forms - one or two sentences, in English and German.
- **Your own presets may name workspaces:** a preset in `~/.config/sandbox-ai/presets/` (yours alone, outside every
  workspace) may use `--workspace {folder}`, so one preset can bring all the repositories a project needs; built-in
  presets and those from further preset directories still may not.
- **App, Board: Cut, Copy, Paste.** A right click on a part offers Properties, Set up step by step…, What is this?,
  Cut, Copy, Paste and Remove (Remove and Cut greyed out for the agent, proxy and network, the tooltip says why); the
  empty board offers Paste there. Ctrl+X, Ctrl+C, Ctrl+V and Delete do the same on the canvas. Copied parts keep
  their settings and the connections among them, on the system clipboard (so across project tabs), never a value
  that looks like a credential; a part a board has once is not pasted twice (a message names it), and a connection
  to it goes to the board's own. Every paste, cut and removal is one step of Undo. The parts list no longer shows a
  line on how to use it: its tooltip and (?) say it.
- **App: what to enter as a ruleset.** The ruleset files field (the Approvals and rules part on the Board, Ruleset
  file on the Start page) shows an example path and what a ruleset does, a short GitHub example in its tooltip, and
  two buttons: New from example… writes a starter ruleset (GitHub without gists and issue writes, a release asked
  first, an MCP example) to a file chosen outside every workspace (one inside a workspace is refused with the
  reason: the agent could change its own rules) and adds it; Check asks the launcher (a dry run) whether it reads
  the files and shows their rules or why it refuses one. The help's Rulesets topic has the example too.
- **Doctor: which sandbox-ai answered.** `sandbox-ai doctor` now starts with sandbox-ai itself: its version, where it
  is installed (the user's own or a system installation with its prefix, a package, pip or a checkout, with the path)
  and the Python it runs with, read as the hosts list reads `version --verbose` (nothing is asked over the network;
  whether an update is there stays `sandbox-ai update --check`'s and the hosts list's). `--json` gives it as the
  first entry with `"id": "sandbox-ai-version"` and `version`, `kind`, `path`, `prefix`, `python`. The Doctor tab of
  the app's Hosts page and the web's doctor (its page and a host's Test) head the checks with it ("sandbox-ai 0.1.79
  on ct1 — system installation in /usr/local (…), Python 3.12.3"); for an older host whose doctor does not say it,
  with the version the hosts list knows, marked "(from the hosts list)".
- **App: Settings and the administrator's policy have room for their text.** In German (and partly in English) long
  check boxes and labels ran past a tab's right edge (a sideways scroll bar) and the last tab titles hid behind
  scroll arrows. Check box texts now wrap (the whole box still toggles; its text and accessible name stay), a long
  label goes above its field, a long path may break after each "/", the telemetry choice no longer widens its tab,
  and the dialog opens wide enough for every tab title (790 px in English, 906 px in German; never wider or higher
  than the screen, at most 600 px high, at least 420; each tab scrolls downwards). "Close" is translated.
