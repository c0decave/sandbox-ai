# sandbox-ai 0.1.79

0.1.79 carries everything listed for 0.1.78 (docs/releases/v0.1.78.md; 0.1.78 was never published: it only marked
the state installed from the repository while the reviews went on), and on top:

- **Version numbers** go up with every larger change from now on: x.y.z → x.y.(z+1); after x.y.249 comes x.(y+1).0,
  after x.49.249 comes (x+1).0.0 (`scripts/bump_version.py`).
- **App, Board**: the right mouse button drags the view like the middle one (a right click without moving opens a
  menu: add a part there, select all, fit, zoom 100 %, arrange, undo/redo; on a part Set up step by step…, What is
  this?, Delete; the menu key too). A click no longer snaps every part to the grid and adds a "Move" to Undo (the
  content jumped); only the left button selects and moves, and only the parts it moved snap. Middle-button panning
  works (it never did: Qt hand-drags with the left button only). A part's text wraps to at most three lines inside
  it (the part grows, "…" when more is left, all of it in the tooltip and the inspector) instead of running over its
  edge. Selecting a part brings back the inspector's panel when it had been closed (floating or docked).
- **App: the window keeps answering while work runs.** A kit change (Add plugin, a marketplace, a skill, a hook;
  cloning a marketplace takes a while), a host's update or installation show a busy bar naming what runs, a Cancel
  that ends the command with everything it started, and what sandbox-ai writes as it comes; the outcome is said in
  the page (wrapped, plain text), one change runs at a time and a second click starts nothing. The status bar says
  which pages have work running ("Running: Kits & plugins…"). What still ran on the window's thread now runs in the
  background: the registry reads that may ask Podman about ended runs (the project switcher and menus, the Files
  page's folders, the Activity page's sources, the Board's live rows, Start at login); the approvals' scan and the
  question when quitting read only the registry's files and /proc; the check whether Chromium's sandbox can start
  (before each terminal tab, a child process) runs in a thread while the window goes on. Tests: each long action
  clicked against a backend that takes 2 s (the window must answer every 200 ms), every button of every page
  clicked with every slow backend call faked (none may run on the window's thread), and an AST check that holds
  every slow backend method, in every module of the app, to the background.
- **App: buttons are actions, toggles look like toggles.** A clicked button no longer looks pressed afterwards
  (Home on the Files page: some themes drew the focused button as pressed; focus is now a border there, and the
  Files page's buttons take no focus from a click). "Details" and "Advanced options" are disclosures with an arrow;
  the "+" menu's projects are actions (an open one says "(open)"), the project switcher a radio choice. The Files
  page's two panes split half and half and keep the division you drag.
- **App and web: the names of secrets and VPN profiles are offered where a field takes one.** Each field that takes
  the name of a stored secret or of a VPN profile is a list to choose from with the chosen host's names (read in the
  background over SSH for another host: `secrets list`, names only, never a value; `vpn list --json`), typing a name
  that is not there yet still works: the VPN profile's key, password, account and bridges secret, an LLM server's API
  key secret and VPN profile (its Test connection too), the wizard's model server, "Use a stored secret" of a Git or
  publish login, an identity's logins, MCP add and start `--vpn`, the Board's `--vpn` (and its step-by-step guide),
  `--secret-env`, `--api-key` and `--git-token-secret` on the Start page and the Board ("+" adds one; HOST= and URL=
  lines are completed), and a sandbox-ai preset's secret value. Another host chosen reads its names (a late answer for
  the one before is dropped); an older host that cannot list them leaves the field typed in, the tooltip says why; a
  secret or profile added or removed on the Credentials page reaches every open field. The web interface offers the
  same through a list of suggestions (VPN, LLM servers, MCP servers, identities, a preset's secret value).
- **App, Board panels**: the inspector (properties) waits as a narrow strip at the right edge of the board and slides
  out when a part is clicked (Esc, a click on the empty board or its arrow slide it back); View > Panels >
  Properties as a separate window makes it a window of its own that opens on a click instead (remembered). The
  security score and the findings are a panel of their own, closed until asked for (the score's button above the
  board or View > Panels), and no longer move with the inspector.
