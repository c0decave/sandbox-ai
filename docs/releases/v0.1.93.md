# sandbox-ai 0.1.93

**Security: nothing leaves past Tor or a VPN any more.** A start with `--vpn` (a Tor profile above all) let traffic
out from your own address in several ways; all are closed:

- **MCP servers** run in sandboxes of their own and went out directly, outside the start's VPN (a Tor start's
  browser server showed the user's home address). Now every MCP server that reaches the network runs behind the
  start's VPN; one with a VPN of its own keeps it, behind Tor it must be Tor too; a Bubblewrap-only server with
  network is refused; `mcp attach --live` and `mcp start --for` follow the same rule. An image whose user is Tor's
  uid (also written as `0950`, or through its own `/etc/passwd`) is refused.
- **Host ports** (`--allow-host-port`, an `--llm` server on this machine, a localhost Git login) lie past Tor:
  refused with a Tor profile unless `--vpn-bypass-host-ports` says you mean it.
- **The host's browser** no longer opens pages a Tor run asks for; the launcher no longer asks an `--llm` server
  anything from your address when a VPN is given.
- **The checks during the run** now really run in agent pods and in every server's pod, and with Tor any exit the
  Tor Project does not know ends the run (`--vpn-check stop`).
- The Tor presets: the profile must be a Tor profile, the image variant is built with
  `sandbox-ai build --variant tor` (`build tor` is the Tor VPN's own image), and they name no unpublished server.

**The desktop app**

- **No window blocks the app any more.** A dialog is a window of its own; the page it came from waits behind a veil
  (its folder, host or board cannot change under the question), the rest of the app stays usable. The **log** has a
  window of its own (View > Log in its own window, **Ctrl+Shift+L**, also from inside a dialog), so what a dialog
  reported can be read and copied while it is open. Dialogs fit on the screen.
- **No more flicker at the start** on tiling window managers (widgets were shown as windows of their own for a
  moment), and the first terminal tab no longer re-creates the main window.
- **Mouse side buttons:** back and forward through the pages shown, the third opens Settings (also Alt+Left/Right).
- **Several rows at once** (Ctrl, Shift, Ctrl+A) in every list where it makes sense, with one question for all
  (sandboxes, secrets, logins, identities, VPN profiles, hosts, kits, LLM servers, image variants, teams, MCP
  servers, remembered approvals); **Ctrl+C and Copy** in every list and table; visible column separators;
  notifications' text can be marked and copied.
- **Sessions** are grouped with everything that belongs to them (MCP servers, helpers, team members; servers of no
  start apart), and a start opens one tab, not one per part.
- **File manager:** `..`, drag and drop (between the panes, from and to other programs), a text and a hex editor
  on double click, a context menu (copy, cut, paste, move, rename, delete, new folder, properties with owner and
  permissions), no shifting panes on a folder change.
- **Board:** what a preset needs is prepared before the start - a missing identity is made, an image variant of a
  recipe is made and built, a Tor profile made, MCP servers added from their catalogs - then the start goes on.
  Values still to fill in are asked for by the preset's names; a part outlined in red says why. OK and Cancel close
  the properties. With a model server the Model field says which model it gives, and the guide offers its models.
  The same preparation runs on the Start page.
- **Kits & plugins** reorganised (actions above each list; "Add plugin" puts it into a kit, "Install the kits'
  plugins" downloads); installing runs in the background, the output in the log window.
- One answer on a question's notification settles it everywhere (no second Allow).
- Moving a session to another host checks what the start there will meet (folders, MCP servers, the agent's
  login, a session of that name), never leaves a half-made session there and never deletes one it cannot tell
  apart; its Close button works again.

**Fixes**

- `sandbox-ai logs` and the Statistics page read a bounded amount (they read every run's logs whole and could
  freeze the machine); `activity` and `safeguards` with `--tail` read from the end.
- OpenCode's brief red "socket connection was closed unexpectedly" with a local model server: a connection the
  server closed while idle is now closed for the client too.
- A refused name lookup names the process that asked (looked up before the refusal goes out); the sandbox's own
  host name is in its `/etc/hosts`.
- MCP servers under Bubblewrap start again (their command reached bwrap through a pipe it reads options from only).
- Resume names an MCP server it cannot find and how to resume without it; a first start that fails keeps no session.
- `sandbox-ai plugins` keeps the plugin store's index (the sandcastle plugin was "not found").
- A TLS refusal says whether the program refused the session CA or just went away.

**Faster:** the commands the app polls take 40-60% less time (they run in one process from cached bytecode and no
longer load the launcher), a dry run about half, the app's first paint about a quarter less; large folders list
six times faster.

**MCP servers (sandbox-ai-mcp):** the catalog is published and signed - binwalk, brave-search, capa, duckduckgo,
openosint, osint-mcp, playwright, radare2, searxng, signal, telegram, telegram-user, web-fetch; each built from
pinned sources (every release at least 14 days old), its shipped code reviewed in full, smoke-tested with
sandbox-ai under Podman. `sandbox-ai mcp catalog` lists them, `sandbox-ai mcp add NAME` adds one. Their Bubblewrap
form follows once this release is public (the CI checks it with the published sandbox-ai).
