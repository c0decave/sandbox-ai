# sandbox-ai 0.1.92

**Signed releases.** From 0.1.92 on every release signs its `SHA256SUMS` with the project's release key, fingerprint
`SHA256:4Of0GsID4w0KNilg2VbymVRcyopNJbbq7K1P1qXg+Ug` (`sandbox-ai version --verbose` shows the keys an installation
trusts; README "Check a download" verifies a download by hand). An installation that trusted no key yet takes it
with this update; from then on `install.sh` and `sandbox-ai update` install only releases signed by it.

**The old single commands are removed** (deprecated since 0.1.30): `claude-sandbox`, `codex-sandbox`,
`opencode-sandbox`, `sandbox-session`, `sandbox-mcp`, `sandbox-wizard` and `sandbox-build-image`. Use
`sandbox-ai claude|codex|opencode`, `sandbox-ai session` (or `list`, `attach`, `pause`, `resume`, `stop`,
`delete`), `sandbox-ai mcp`, `sandbox-ai wizard` and `sandbox-ai build`; scripts that call the old names must be
changed. An update with `install.sh` removes their links.

**A running sandbox**

- **API keys during the run:** `sandbox-ai net allow [RUN] --api-key HOST=NAME[=SECRET]` gives the connection proxy
  a key as `--api-key` does at a start (HOST is opened, the agent only sees the placeholder; the command prints the
  `export NAME=...` line for the sandbox); `revoke --api-key NAME` takes it back. In the app: Credentials, a
  secret's menu, Give to a running sandbox…. Runs started with 0.1.92 or newer.
- **`sandbox-ai rules check|show|reload`:** check ruleset files (or yours, the policy's and the project's), list the
  rulesets a start would have with where each comes from, and make a running start read its HTTP rules anew - the
  administrator's policy and the security mode stay as they were. In the app: Reload rules on the Sandboxes page,
  Check and All rules… beside the ruleset field.

**Kept starts**

- **Other options at a rebirth:** `sandbox-ai resume NAME [--restart] --gui --cpus 4 --allow-host H` changes a kept
  start's saved options (one value replaces, a list adds), `--drop-option OPTION[=VALUE]` takes one out; checked as
  a new start first, refused changes nothing. In the app: Resume with….
- **`sandbox-ai resume NAME --restore-home [--path PATH] [--yes] [--json]`** puts back the recorded text of the
  start files a stopped start's HOME changed or lost (small text files, never keys or tokens), each shown and asked.
  In the app: Restore HOME after a HOME review.
- The wizard asks for the project keys `"name"` and `"keep"`, and `wizard edit` keeps them.

**VPN and Tor**

- The address and the resolvers are **checked again during the run** (every 600 s, `"recheck"` in
  `~/.config/sandbox-ai/vpn/checks.json`; `0` only at the start): a leak ends the run, or with `--vpn-check warn`
  is reported. An MCP server behind a VPN stops on a leak too.
- **Names allowed during a run** (`net allow --allow-host`, approved lookups) are looked up by the VPN's own
  resolvers, no longer on the host.
- **`sandbox-ai llm check|models|status`** of a server added with `--vpn` go through that VPN, so a server only the
  VPN reaches is checked from where the agent reaches it.
- **`sandbox-ai vpn rotate NAME`** gives a Mullvad profile's device a new WireGuard key (refused while a sandbox
  uses the profile).
- With a remote Podman engine (`--podman-url`) the address check compares with the engine's own public address.
- Tailscale in the VPN image is pinned to v1.104.2 (was `stable`).

**LLM servers:** the model's **context window**, as the server reports it, reaches Codex (`model_context_window`)
and OpenCode (`limit.context`, `limit.output`); `llm models` remembers it for later starts.

**macOS:** the host side of stages 2-5 is in the code - an interactive start is a detachable tmux session again,
attach, `net allow|revoke` and `limits` go through `podman exec`, `--allow-host-port` and `--llm` reach the Mac's
loopback, `xdg-open` opens with `open`, notifications through `osascript`, secrets in the Keychain (Claude Code's
Keychain login: `sandbox-ai login claude`), the app's Start at login is a LaunchAgent and terminal windows open in
Terminal or iTerm. A macOS CI job checks the process lookups, the Keychain and `install.sh` on a real Mac, but
**none of it has run against a real `podman machine` yet**; MCP servers from catalog images and
`mcp attach --live` are still refused there, and `workspace add|remove`, `usage` and `devices` during a run are
Linux only for now.

**Images:** the agent images carry Qt's libraries (libEGL, libGL, xcb) and gdb, so a desktop app's tests run
offscreen in a sandbox - the new preset `sandbox-ai-tests` runs sandbox-ai's own test suites. **Rebuild** to get
them and the Tailscale pin: `sandbox-ai build all` (or the agents you use), and `sandbox-ai build vpn` if you use a
VPN profile.

**Performance:** the connection proxy sets `TCP_NODELAY` (a keep-alive request through it took 47 ms, now about
1 ms - every API call of an agent passes it); a start plans about 10% faster; `sandbox-ai approvals list` 88 -> 69 ms.

For maintainers: `scripts/live_check.py` runs every live suite that needs no login against this host's Podman and
Bubblewrap and writes a report (a step of RELEASING.md now).
